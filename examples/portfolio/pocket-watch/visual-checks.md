## Iteration log

1. **v1** — DOME_HALF = DIAL_RADIUS + 0.8, square 5×5 NURBS control grid. Dome rendered as a square slab; G3 failed.
2. **v2** — Switched to polar control grid (radial × angular). Dome circular but had a visible seam wedge at angle = 0; G3 failed.
3. **v3** — Increased angular resolution to N = 12. Seam smaller but still visible; G3 failed.
4. **v4** — Added explicit `periodic: { u: false, v: true }` with periodic V knot vector. Seam closed; G1/G3/G5/G7 pass but opaque dome buried the numerals; G4 failed.
5. **v5** — Shrunk `DOME_HALF` to 0.83 × DIAL_RADIUS and moved numerals OUTSIDE the dome rim. All gates pass but lens reads as a small opaque disc, not a domed glass crystal, and the lanyard loop was an extruded 2D arch silhouette ("a bow") that reads as a flat blade with no chain-passable hole. User rejected: *"lens is shit, not transparent, and small"* + *"the top mount is strange"*.
6. **v6** —
   - Crystal: replaced `.color('#dfeef4')` with v0.8 `.material({ transmission: 0.95, ior: 1.76, roughness: 0.04, clearcoat: 0.4 })`. Dome enlarged to `DOME_HALF = DIAL_RADIUS * 1.05` (rim 5% past dial radius, as on a real crystal). Numerals moved INWARD to `NUMERAL_RADIUS = 8.0` mm so they sit under the dome and read through the glass.
   - Lanyard loop: replaced the extruded arch silhouette with a `torus(majorR=5, minorR=1.2)` rotated so its axis is world-Y (through-hole faces the camera). Subtracted the lower halfspace at `z < LOOP_BASE_Z` so the cut produces clean semi-tube cross-sections. Added a short pink "bail post" cylinder bridging the frame top to the torus tube — needed because lifting the torus above the crown knob otherwise leaves the loop floating.
   - Renderer wiring fixes uncovered during v6 (the existing API documented transmission in `SKILL.md` but no demo had exercised it before): added `lookupSourceMaterial` helper (peer to `lookupSourceColor`) so `Shape.material()` set on the source of `assembly.part(name, shape)` survives the SceneBackend fan-out; extended `SceneBackendPart` to carry `material?: PBRMaterial`; threaded the material through `featureMeshing.ts`'s SceneBackend path; added a PMREM RoomEnvironment-based `scene.environment` in `ViewerPane.tsx` so MeshPhysicalMaterial transmission has an IBL to sample; flipped the `forceFullOpacity` and `buildMeshFromFace` paths so transmissive materials keep `transparent: true` + `FrontSide` (DoubleSide produces self-occlusion artifacts in the transmission render pass).
   - Interference: zero pairs at ε = 0.01 mm³ (`kernelcad interference`).
   - User feedback after v6 demo.mp4: *"Well, generally fine, but top part is not hangable, it connects to the winding wheel!"* — bail post (centered at x=0) and crown stem (also at x=0) were coaxial, so from front + iso views the pink bail and the yellow crown fused into a single tower. G7 still passed in isolation but the loop didn't read as *hangable* — lifting it would lift the crown with it.

7. **v7** — Bail/crown decoupling (Option B: crown to the side).
   - **Crown axis offset.** Introduced `CROWN_X_OFFSET = 5.0` mm. The crown bore in the frame, the crown bore in the case, the crown stem, and the crown knob all now ride on (x=5, y=0, ·) instead of (x=0, y=0, ·). The frame's `fixed` anchor for the crown updated to `[CROWN_X_OFFSET, 0, CROWN_STEM_END_Z]`. The bail (post + half-torus) stays at x=0.
   - **Why x=5.0 specifically.** The casePocket octagon (half-flat = `CASE_FLAT + 0.8` = 18.3 mm) has its diagonal flat starting at x = 18.3·tan(π/8) ≈ 7.58 mm on the top face. The crown bore radius is 1.7 mm, so to keep the bore intersection clean (only meeting the casePocket TOP face, not its diagonal corner — which would produce sub-mm intersection edges that fail the frame's `.fillet(0.6)` blend solver), we need `x_center + 1.7 < 7.58` → `x_center < 5.88`. Picked 5.0 mm to leave 0.88 mm of safety margin.
   - **Crown knob shape.** Replaced `cylZ(1.2, 1.7, ...)` (smooth circular cylinder) with `extrudePolygon(hexPts, CROWN_KNOB_LEN)` — a 6-facet hex prism. Reads as a faceted winding wheel from front + iso + side views (visible in `hero-frame.png` and rotate frames at t≈1s and t≈3s of `demo.mp4`), not a generic knob.
   - **Bail post height.** With the crown moved off-axis, the bail post no longer has to lift above the crown knob (z = 24.8 → was the previous `BAIL_POST_BASE_Z = 25.2`). Lowered `BAIL_POST_BASE_Z` to `FRAME_FLAT = 23` so the bail sits directly on the frame top flat (visibly anchored, no floating gap). Lowered `loopCenterZ` from 31.5 to 30.5 so the torus tube outer-bottom (z=24.3) just clears the post top, and the whole bail-loop assembly reads snugger to the case.
   - **Decoupling distances (measured against the gate ≥ 4 mm).** Bail centerline x = 0, crown centerline x = 5.0 → horizontal centerline separation = 5.0 mm. Closest surface-to-surface gap = 5 − bail-post-r(0.9) − crown-knob-vertex-r(1.7) = 2.4 mm of air. Vertical band overlap remains, but they're in different x-columns so the silhouettes read as TWO objects.
   - **Interference re-verified.** `kernelcad interference build.kcad.ts` → "No interferences detected (96 parts, 262 comparisons, ε=0.01mm³)." Two extra comparisons vs v6 (260 → 262) because the hex-knob part now has a slightly different bounding-box overlap with the bail (caught by the broad-phase prefilter then rejected on the narrow-phase BREP test).
   - **Visual gates re-passed.** G1–G9 unchanged (crystal, frame, dome, numerals, screws, transmission, loop, "reads as pocket watch", interferences). Added G10 (bail-crown distinct) and G11 (crown reads as faceted winding wheel) — both pass; see `hero-frame.png`.
   - **Artifacts regenerated.** `hero-frame.png` and `demo.mp4` re-rendered via `scripts/captureRotateOnly.ts`. `panel.png` re-composed standalone using `composeStaticPanel` (prompt + updated source + new hero + score) so all four quadrants of the panel reflect v7 geometry. Vite dev server bound to 127.0.0.1:5180 during capture (5173 occupied by a sibling worktree); script extended with `VITE_PORT` env override so future workstreams can run two rotate-only captures in parallel without port collisions.

8. **v8 (current)** — Pendant-driven top section that matches the reference photo's pop-art octagonal pocket-watch silhouette (substantial pink pendant carrying the crown out of its top center, slim oval bail with two stub mounts, leaning pink ribbon strap).
   - **Reverted crown-side-offset (v7's Option B).** `CROWN_X_OFFSET` is back to `0`. The crown bore in the frame, the crown stem, and the crown knob now ride on the centerline. The case crown bore reverted to x = 0; frame crown bore reverted to x = 0.
   - **Pendant block (new).** Pink rectangular slab (`PEND_HALF_X = 5`, `PEND_HALF_Y = CASE_DEPTH/2 = 4`, `PEND_HEIGHT_Z = 5.5`) built with `extrudePolygon` of a 4-point rectangle, sitting flush on the frame top flat (`PEND_BASE_Z = FRAME_FLAT = 23`). `.fillet(0.8)` rounds all edges. Crown bore (`PEND_BORE_R = 1.65` mm) cut vertically through the pendant; the crown stem now exits the pendant top (z = 28.9) rather than the case top directly. Pendant fillet is applied BEFORE the bores — applying fillet AFTER produces sub-mm edges OCCT's blend solver can't handle (originally tried `.fillet(0.6)` after; OCCT C++ exception during `Build`; switched to pre-fillet order which evaluates cleanly).
   - **Pendant side hex screws (new).** Two black hex screws (`PEND_SCREW_R = 1.1` mm, 6-sided prism extruded 0.5 mm along ±X) recessed into counterbores cut along ±X axes at z = 26.0. The counterbore + screw geometry required care: the screw prism's extrusion direction (+Z pre-rotation) had to map to the OUTSIDE of the pendant after rotation. Got the `rotate([0,1,0], ±90°)` direction wrong on the first pass (used −90° for xSide=+1, which sent +Z to −X via the right-hand rule, leaving the screw body INSIDE the pendant solid → 1.4 mm³ interference). Corrected to +90° for xSide=+1 and −90° for xSide=−1. Counterbore origin shift had a parallel bug on the left side (the original `xSide * (PEND_HALF_X - CB_depth)` formula put the left counterbore on the wrong side of the pendant flat); corrected to use `baseX = ±PEND_HALF_X − 0.6` so the bore always straddles the outer face.
   - **Oval bail (new).** Replaced the v7 half-torus bail with an oval flat-ring ring constructed as `extrudePolygon(ovalOuterPts, BAIL_Y_DEPTH).subtract(extrudePolygon(ovalInnerPts, ...))`. Outer ellipse semi-axes 2.6 × 3.4 mm → aspect ratio 1.31:1 (taller than wide). Wall thickness 0.8 mm. Through-hole opens along ±Y (camera sees the opening directly from the front view). Two stub posts at x = ±2.6 (5.2 mm apart) connect the oval bottom to the pendant top — the stub-X offset had to be widened from the spec's nominal "3-4 mm apart" because at x = ±1.6 the stubs interfered with the centered crown knob's 1.7 mm vertex radius in the z = [28.9, 30.0] overlap band. Bumped to ±2.6 so each stub has 0.3 mm clearance from the knob vertex.
   - **Bail-vs-crown vertical clearance.** Crown knob top z = `PEND_TOP_Z + 0.4 + CROWN_KNOB_LEN` = 30.1; bail oval bottom (outer edge) z = `BAIL_CENTER_Z − OVAL_AX_Z` = 30.5 → 0.4 mm vertical air. Initial layout had only 0 mm vertical air (oval bottom at 30.0 vs knob top 30.1), producing 0.054 mm³ interference between the crown and the oval. Lengthened `BAIL_STUB_LEN` from 1.5 → 2.0 mm to lift the oval clear.
   - **Ribbon strap (rebuilt).** Replaced the v7 vertical box with a 4.5 × 0.6 × 7.5 mm pink rectangle leaning forward 15° (rotate([1,0,0], -15)) and translated forward in Y so it sits in front of the bail tube — no interference, but visually it "passes through" the oval opening in the iso pose. Apex sits at roughly z = 41 above the frame top.
   - **Top-stack height.** Bail apex (z = 37.3) is 14.3 mm above the frame top — within the 13-15 mm target window from the spec. The ribbon adds another ~7 mm above that to z ≈ 44.
   - **Interference re-verified.** `kernelcad interference build.kcad.ts` → "No interferences detected (99 parts, 266 comparisons, ε=0.01mm³)." Three new parts vs v7: pendant + 2 pendant side screws + 1 ribbon (already counted in v7) + bail with stubs (replaces v7 loop; same single-part count). Net: +3 parts → 96 + 3 = 99. (Pendant body counts as 1 part, pendant-side hex screws as 2 parts.)
   - **G16 (waffle texture).** The PBR `PBRMaterial` interface (`src/shared/intent/material.ts`) currently exposes only `baseColor / metalness / roughness / clearcoat / clearcoatRoughness / ior / transmission / sheen`. No `map`, `baseColorMap`, or `texture` field — there is no author-time way today to attach a diffuse texture to a Shape. Geometric tapisserie bumps are the only path that does not require a renderer change. Existing TAP_PITCH = 1.4 mm grid of 0.9 × 0.9 mm raised bumps remains in place; they render through the transmissive crystal as a visible waffle pattern in `hero-frame.png`. **Texture-map path: DEFERRED — would need `PBRMaterial.map?: string` plus a renderer-side texture loader.**
   - **Artifacts regenerated.** `hero-frame.png` and `demo.mp4` re-rendered via `scripts/captureRotateOnly.ts` (4 s rotate, 120 frames, ~300 s wall time). Vite dev server bound to 127.0.0.1:5181 for this run (other ports busy on sibling worktrees).
