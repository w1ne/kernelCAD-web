# v0.4-rc7 Quality Pass — Design

**Date:** 2026-05-01
**Milestone:** v0.13.0-rc.7 (NORTHSTAR roadmap step in v0.4-rc trajectory: tighten edge/face selection foundation)

## Why

A code-quality audit of rc.6 surfaced ten issues across four levels of severity. Four of them are agent-hostile in ways that the spec-compliance check missed: the type system promised features the kernel didn't implement, diagnostic hints existed without their codes ever being emitted, module-level mutable state created concurrency hazards, and a CHANGELOG-promised flow had no working agent-facing path. The remaining six are smaller agent-friction issues — silent no-op fields, dispatch fragility, lumped diagnostic codes — that compound as more features land on top.

rc.7 is a quality pass: no new geometric capabilities, just bring the rc.6 surface to the standard the CHANGELOG already claims. New geometric features (sweep, beziers, partial revolves) resume in rc.8 on a tightened foundation.

## Goals

1. Every `Shape.fillet/chamfer/shell` argument shape that typechecks at capture works at lowering — no type-vs-runtime gaps.
2. Every diagnostic code mentioned in the `whyDidThisFail` hint table is reachable from at least one execution path. No dead hints.
3. No module-level mutable state in the lowering pipeline. Concurrency-safe by construction.
4. Every CHANGELOG-claimed agent flow has an end-to-end test that exercises the agent's actual entry point (script runtime or MCP).
5. Diagnostic codes are specific enough that an agent can decide the next action from the code alone (rename a label vs wait for a feature vs adjust geometry).

## Scope

### Critical fixes (C1–C4)

**C1 — `pickFace` query/label dispatch parity with `pickEdges`.**

Today `pickFace` only handles `FaceRef.canonical`. After rc.7, it dispatches on `query` and `label` variants the same way `pickEdges` does:

```
pickFace dispatch:
  no faceRef → existing canonical-canonical-fallback path
  ref.kind === 'query' → resolveFaceQuery → pick first face → return
  ref.kind === 'label' → labelToFaceRef → resolve to face on extruded shape → return
  ref.kind === 'canonical' → existing canonical resolution
  else → 'feature.face-feature.face-ref-not-supported'
```

Effect: `box(10,10,5).shell(1, { face: { atZ: 5 } })` works after rc.7. The current "v0.2-alpha" message in `feature.face-feature.face-ref-not-supported` is replaced with a code-aware error that names the unsupported variant.

**C2 — Convert `Error` throws to `CompilerDiagnostic`s along the agent path.**

A new `KernelError` base class with a typed `code` field. Kernel throws use it:

```typescript
class KernelError extends Error {
  constructor(public readonly code: string, message: string) {
    super(message);
  }
}
```

Three call sites switch from plain `Error` to `KernelError`:
- `PathBuilder.label()` validation throws → `code: 'feature.path.label-without-segment'` and `code: 'feature.path.duplicate-label'`
- `selectEdge()` ambiguity throw → `code: 'feature.edge-feature.ambiguous-selection'`

The `runScript` exception handler (single touchpoint) catches `KernelError` and yields a `CompilerDiagnostic` with the kernel-specified code. Generic `Error`s still produce `cli.script.exception` as today.

The existing `Error` throw shape stays at the script-runtime boundary — no behavior change for callers who don't go through `runScript`. Tests that match on error message text still pass.

**C3 — Thread records through `pickEdges`/`pickFace` as a parameter.**

The signatures change from `pickEdges(record, base)` to `pickEdges(record, base, records)`. The existing `setLoweringRecords` module variable is removed. Same for `pickFace`.

The lowerer reads `records` from `inputs._allRecords` (no change at the inputs interface — that part of rc.6 was already correct), then passes it to `pickEdges`/`pickFace`/`labelToEdgeQuery` directly. No global state.

**C4 — Expose `selectEdges`/`selectEdge` to the script-runtime + add e2e test.**

Today `selectEdges`/`selectEdge` live in `src/backends/occt/edgeQueries.ts` but are not in the script-runtime globals. Agents can't write `const edges = selectEdges(myShape, { atZ: 5 }); shape.fillet(1, edges)` from a `.kcad.ts` file.

The script-runtime registers a thin wrapper that:
- Resolves the `Shape` (the agent passes a captured `Shape` proxy) to its lowered `OcctBackend`
- Calls the backend `selectEdges`/`selectEdge`
- Returns the resulting `EdgeSegment[]` / `EdgeSegment`

E2E fixture `tests/e2e/fixtures/preselected-edges.kcad.ts` exercises the full round-trip: `selectEdges` → pass result to `.fillet(r, edges)` → produce STL.

This requires lowering the shape eagerly during capture (rather than just registering it). For `selectEdges` to work at script-runtime, the `Shape` proxy needs an evaluated `OcctBackend` available. Two implementation options:
- **Eager:** every `Shape` proxy method that can be selected against (currently `box`, `cylinder`, `sphere`, `extrude`, `revolve`, plus operations that produce them) lowers eagerly when registered. This is simple but doubles work for shapes that are immediately consumed by booleans.
- **Lazy:** introduce a `lower()` method on `Shape` that the script runtime triggers when `selectEdges`/`selectEdge` is called against a not-yet-lowered shape. Agents call it implicitly through `selectEdges`; explicit calls are also fine.

rc.7 uses **lazy** — keeps the existing capture flow unchanged for non-selecting code, only pays the cost when an agent actually selects.

### Important fixes (I1–I6)

**I1 — Replace structural duck-typing in `buildEdgeFeatureRef` with a closed-key whitelist.**

`buildEdgeFeatureRef` (in `src/capture/captureSession.ts`) currently uses `'face' in selector && !('id' in selector)` to discriminate `{ face: ... }` from an `EdgeSegment`, and `'id' in selector && 'midpoint' in selector` for segments. After rc.7:

```typescript
const EDGE_QUERY_KEYS = new Set([
  'atZ', 'atX', 'atY', 'near', 'within', 'parallel', 'perpendicular',
  'convex', 'concave', 'minAngle', 'maxAngle', 'ofCurveType',
  'tolerance', 'angleTolerance',
]);

function isEdgeQuery(s: object): s is EdgeQuery {
  return Object.keys(s).every(k => EDGE_QUERY_KEYS.has(k));
}

function isEdgeSegment(s: object): s is EdgeSegment {
  return 'id' in s && 'midpoint' in s && 'direction' in s && 'curveType' in s;
}
```

If neither matches, the dispatch returns a `feature.edge-feature.invalid-query` diagnostic at lowering — fail loud, not silent.

**I2 — Populate `EdgeSegment.normalA/normalB`.**

`computeDihedral` already extracts both normals (lines 209-211 in `edgeQueries.ts`); `toEdgeSegment` discards them. Wire them through. Zero additional cost.

**I3 — Implement `FaceQuery.inPlane`.**

Add to `resolveFaceQuery`:

```typescript
if (query.inPlane) {
  const target = planeNormal(query.inPlane);
  faces = faces.filter(f => {
    const n = f.normalAt();
    return isParallel([n.x, n.y, n.z], target, angleTol);
  });
}
```

Behavior: face's surface normal aligned with the plane's normal AND face centroid lies within `tolerance` of the plane (otherwise we'd match every parallel face anywhere in space — agents expect "in" to mean "in").

**I4 — Split `feature.face-feature.label-not-resolvable` into 4 specific codes.**

Replace the single code with:

| Code | When | Hint |
|---|---|---|
| `feature.label.unknown-name` | Label name not present on any segment of the upstream sketch | "Label '<name>' not found. Use `list_face_labels` MCP tool to see available labels on this sketch." |
| `feature.label.no-upstream-sketch` | Fillet/chamfer/shell uses label but base shape isn't sketch-derived | "Labels work on shapes built from a path() sketch (extrude / revolve). Apply the label to the sketch upstream." |
| `feature.label.unsupported-base` | Label used on a revolve/sweep/etc not yet supported | "Labels currently support extrude only. Revolve labels land in a future rc." |
| `feature.label.mixed-convexity` | Label probe matched a mix of convex and concave edges (typically a reflex corner) | "Labeled segment sits at a reflex corner — probe matched mixed convex/concave edges. Either split the label, or refine with `{ face: { label: 'name', convex: true } }`." |

The old `feature.face-feature.label-not-resolvable` code stays in the hint table for one rc as deprecation grace, marked with a deprecation note.

**I5 — Rename `_allRecords` → `records`.**

`ResolvedInputs.records: FeatureRecord[] | undefined` — drop the leading underscore. The field is part of the legitimate lowerer contract; the underscore was admitting a workaround that no longer applies after C3. JSDoc explains: "Optional read-only access to the full record list for ops that need to walk upstream features (e.g. label resolution)."

**I6 — Pre-flag mixed-convexity labels with `feature.label.mixed-convexity`.**

In `labelToEdgeQuery`, after resolving the probe-point query, inspect the resulting edges' dihedrals. If the set has both convex and concave members, return the new diagnostic instead of the edge list. Agents either split the label upstream or refine with `{ convex: true }`.

### Bonus items (small, agent-first)

**B1 — `chamfer` and `shell` integration tests with EdgeQuery / FaceQuery.**

rc.6 only tested `fillet` with EdgeQuery. Add 2 tests:
- `box(10,10,5).chamfer(0.5, { atZ: 5 })` — top edges chamfered, volume reduced
- `box(10,10,5).shell(1, { face: { atZ: 5 } })` — top face removed, hollow box

Coverage symmetry — important because C1's `pickFace` widening landing without a shell test would mask a regression.

**B2 — Document `EdgeQuery.near` semantics.**

JSDoc on `EdgeQuery.near` clarifying: "Sorts results closest-first; does NOT filter. Combine with other query keys (`within`, `tolerance`) to filter, then `near` to disambiguate. `selectEdge` uses `near` to pick a single result from multiple matches."

## Architecture

### Files modified

- `src/backends/occt/edgeQueries.ts` — populate `normalA/normalB` (I2), implement `FaceQuery.inPlane` (I3), `selectEdge` throws `KernelError` (C2), `EdgeQuery.near` JSDoc (B2)
- `src/backends/occt/edgeSelection.ts` — `pickEdges` and `pickFace` take `records` param (C3); `pickFace` adds query/label dispatch (C1); `labelToEdgeQuery` adds mixed-convexity check (I6); diagnostic codes split (I4); remove `setLoweringRecords` and `loweringRecords` (C3)
- `src/backends/occt/occtLowerer.ts` — pass `records` directly to `pickEdges/pickFace`, no global setter (C3)
- `src/backends/backend.ts` — rename `_allRecords` → `records` (I5)
- `src/compute/recomputeEngine.ts` — pass `records` (renamed) to lowerer
- `src/capture/captureSession.ts` — `buildEdgeFeatureRef` uses key whitelist (I1)
- `src/capture/sketch.ts` — `PathBuilder.label()` throws `KernelError` (C2)
- `src/script-runtime/runScript.ts` — catch `KernelError` and convert to `CompilerDiagnostic` (C2); register `selectEdges`/`selectEdge` globals (C4)
- `src/capture/proxy.ts` — `Shape.lower()` lazy method for C4 round-trip
- `src/mcp/tools/whyDidThisFail.ts` — 4 new label codes, deprecate old code, near JSDoc references (I4)

### Files created

- `tests/unit/script-runtime/kernelError.test.ts` — verify throws convert to diagnostics

None (no breaking removals — the deprecated label code stays one rc).
