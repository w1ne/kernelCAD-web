# v0.17.0 turbojet hero example + twist-capable loft

Status: design approved 2026-09-18. Base: `origin/develop` @ ef78251a
(worktree `kernelCAD-web-worktrees/turbojet`, branch `feat/v0.17-turbojet-engine`).

## Context

kernelCAD's v0.17.0 release needs a memorable hero artifact that exercises the
mechanical core honestly. A single-spool turbojet cutaway is the target: it
forces revolved casings, lofted twisted airfoil blades, radial blade rows,
can-annular combustors, a rotor stack with bearings, and a ~25-30 part
assembly. Building it against the current kernel has already exposed three
modeling gaps (reproduced with measured evidence, see "Gap evidence" below).
The deliverable is the example **plus** the kernel fixes the example motivates,
in the repo's established "hardware recipe exposes kernel gap; fix at the
kernel" pattern (`kernelCAD-private/docs/specs/2026-09-14-kernel-gaps-design.md`).

Decisions locked with the user:

- Engine: single-spool turbojet cutaway (J85-class), ~1.2 m long.
- Fidelity: exhibit-grade, static (no rotor spin animation).
- Deliverable: hero example + kernel fixes.
- Version framing: upcoming v0.17.0 release example; no git tags/releases created.
- Kernel approach A: twist-capable loft (variableSweep multi-station deferred).

## Gap evidence (measured on the base commit ef78251a, kernel v0.25.0)

1. **Loft has no section twist/stagger, and NURBS sections cannot be stacked.**
   - `planes[].rotationDeg` is silently ignored: a two-section loft with
     `rotationDeg: [0, 45]` exports STEP identical to the unrotated loft
     (bbox `[0..80]×[-4.8..4.8]×[0..100]`, volume 19400 mm³).
   - The authoring skill documents `planes: [{ normal, origin }]`, but the
     capture/lowerer read `{ plane, origin }`; a `normal` key is silently
     dropped (replicad defaults the undefined plane name to `XY`).
   - Spline-bearing sections never get `origin` applied
     (`loftFromSketches` drops it for the NURBS branch), so any stacked
     spline-section loft fails: base build reports
     `ERROR [feature.empty-result] loft_1: loft produced an empty or
     zero-volume solid`.
2. **`Sketch.extrude(depth, { twistAngle })` silently ignores the option.**
   Twisted and plain exports are geometrically identical on the base
   (bbox `[0..40]×[-5..5]×[0..100]`, volume 20000 mm³ both). replicad's
   `twistExtrude` / `extrude({ twistAngle })` exists in the bundled kernel
   (replicad.d.ts `SketchInterface.extrude`) but is not wired.
3. **`variableSweep` only lowers t=0 and t=1.** Three sections fail with
   `feature.kernel-failed: section t=0.5 ... intermediate stations require
   spine subdivision`. Deferred (not fixed in this slice); logged.

## Kernel changes

### G1 — Loft section orientation

- `Sketch.loft(other, opts)` section placement becomes
  `planes: Array<{ plane: 'XY' | 'YZ' | 'XZ'; origin: [number, number, number]; rotationDeg?: Editable<number> }>`
  where `rotationDeg` rotates the section wire in its own plane
  (counter-clockwise looking down the stacking normal).
- Stacked form gains `twistDeg?: Editable<number>` (total twist distributed
  evenly across the N section planes; first section is the reference, last
  section at `twistDeg`).
- Rotation center is `twistCenter?: [u, v]` in section coordinates, default
  `[0, 0]`. It applies to both distributed `twistDeg` and explicit
  `planes[].rotationDeg`, so the author places the stack axis at the section
  origin (or names it once via `twistCenter`). The rotation is about the
  center in each section's own plane; plane `origin` then places the rotated
  section.
- Explicit `rotationDeg` on a plane overrides the distributed shorthand for
  that plane only.
- `spacing` form: sections stack along the loft normal at `z = 0, spacing,
  2·spacing, ...`; only `twistDeg`/`twistCenter` apply (there are no planes to
  carry `rotationDeg`).
- NURBS-bearing sections honor `plane`, `origin`, `rotationDeg`, and
  `twistDeg` in the lift path (fixing the drop-`origin` defect).
- A loft that lowers to a zero-volume/degenerate solid emits an error
  diagnostic (e.g. `feature.loft.degenerate`) instead of reporting OK.
- Existing unrotated lofts (spacing and `{ plane, origin }` forms) must
  produce unchanged geometry; regression-tested against the current outputs.

### G2 — Extrude twist and loud option handling

- `Sketch.extrude(depth, opts?)` accepts
  `{ twistAngle?: Editable<number>; faceLabels?: FaceLabelsMap }`, lowered
  through replicad's twist extrusion so the twist is real geometry.
- Unknown option keys in `extrude` / `loft` option bags throw
  `feature.invalid-args` naming the offending key (defense against silent
  ignores; specifically closes the `twistAngle` no-op).

### G3 — Skill/doc truth pass

- `src/agent/skills/kernelcad-authoring/SKILL.md` (and the `dist/cli` copy
  regenerated by `npm run build:cli`) corrected to the shipped `loft`/`extrude`
  signatures; remove the stale `{ normal, origin }` claim.
- `kernelcad-nurbs` skill note updated: variableSweep intermediate stations and
  per-section orientation remain unsupported (explicit, with the new loft twist
  named as the supported alternative for twisted solids).
- A regression test asserts the documented option keys exist (drift sentinel).

### Tests for G1/G2

- Unit: capture accepts/rejects the new option shapes; lowerer rotates
  sections (bbox + volume of a twisted loft measured against an analytic
  reference); NURBS sections land at their plane origins (non-zero bbox span);
  degenerate loft diagnostic; unknown-option throw; back-compat for existing
  unrotated lofts.
- Integration: a twisted tapered blade fixture evaluated through the CLI and
  exported to STEP with the expected bbox/volume sanity envelope.

## Turbojet model

Single source file `examples/gallery/turbojet-engine.kcad.ts` (examples are
single-file; no import surface), organized in sections with helper functions:

- `bladeProfile(chord, thickness, camber)` → `path()` outline (arc/spline
  airfoil; NURBS outline now supported by G1).
- `blade({ span, rootChord, tipChord, thickness, twistDeg, staggerDeg })` →
  loft through 4-5 sections with taper + rotation, then `.rotateZ(stagger)`.
- `bladeRow({ count, radius, ... })` → `blade(...)` at radius, rotated to
  stagger, `.patternCircular({ count, axis: [0,0,1] })`.
- `disc(stage)` → revolve hub web + rim, unioned with its blade row.

Part list (~26-30 named parts; names are the BOM/durable handles):

- Static: `casing-upper-half`, `casing-lower-half` (revolved shell minus a
  half-space box so the cutaway is real geometry), `inlet-ring`,
  `flange-front`, `flange-rear`, `stator-ring-1..8` (vanes patterned on a
  ring), `combustor-outer`, `combustor-can-row` (8 cans + swirlers),
  `bearing-housing-front`, `bearing-housing-rear`, `nozzle-convergent`,
  `exhaust-cone`, `mount-front`, `mount-rear`, `fuel-manifold`.
- Rotating (single revolute spool): `nose-cone`, `compressor-disc-1..8`
  (disc + twisted blade row each), `turbine-disc-1..2`, `shaft`.

Assembly rules (from the assembly/dispatch research):

- Exactly one articulated joint: `shaft` revolute to `casing-lower-half`
  (axis connectors at both ends, `limitsDeg` bounded); every other part
  `fastened` through matching frame/axis connector shims; world transforms
  pre-baked into each part shape. Mechanism budget (research formula
  `(1 + 3·limitedMates + 3·revoluteMates) × parts`): with one limited revolute
  and ~30 parts, `(1 + 3 + 3) × 30 = 210 < 300` → validated mechanism truth,
  no `unverified` degradation.
- No `dfmSpec` (display assembly; DFM gates would add cost and false
  positives on intentional contacts). No `.toUnion()` on the Scene; exports use
  the per-part compound path.
- Per-leaf `.color(hex)` before booleans: compressor alloy, hot-section
  inconel for turbine, casing, combustor, steel shaft, nozzle.
- All load-bearing dimensions are named `param()`s: `engineLength` (~1200),
  `maxDiameter` (~420), stage counts, `bladesPerRow`, chord/thickness/twist
  per stage, fit clearances.

Blade counts are display counts (param-driven, default 12-18 per row) to keep
the O(rows × count) boolean fuse cost and the O(N²) part-pair interference
check affordable; this is documented as a display simplification, not hidden.

## Verification plan

Deterministic gates (run from the worktree; `npm run build:cli` first):

1. `kernelcad evaluate examples/gallery/turbojet-engine.kcad.ts` — exit 0, no
   error/warn diagnostics.
2. `kernelcad validate ... ` — exits clean, no floating/orphan parts.
3. `kernelcad validate --include-interference --no-include-physics` — BREP
   interference + mechanism truth; `mechanism: real` expected.
4. `kernelcad interference --epsilon 20` — zero pairs, or only pairs declared
   in `solvedModel({ ignore })` and documented as intended contacts.
5. `kernelcad parts --json` — per-part bbox/volume/triangles within expected
   ranges, no runaway part.
6. `kernelcad export step|stl|glb` — succeeds with the default watertight
   verify; STEP inspected with `kernelcad inspect step` for sanity on key
   bodies.
7. Kernel fix tests: targeted vitest suites plus the repo's typecheck/lint
   commands; existing loft/extrude/pattern suites stay green.
8. Visual: `kernelcad render inspect <file> <outDir> --channels
   rgb,mask,depth,normals` for the full engine and for the cutaway
   (`--hide casing-upper-half`); every PNG opened and reviewed for
   proportions, blade rows, floating geometry, occlusion. Passing tests are
   not accepted in place of the visual check.

Gap policy: every gap encountered during the build is recorded in
`examples/gallery/turbojet-engine/README.md` (repro, root cause, fix, or
deferred-with-reason). No gate is loosened or skipped to make the build pass.

## Risks and mitigations

- **Boolean/perf blow-up from blade rows.** Param-driven display blade counts;
  measure `parts --json` triangle counts and evaluate wall time early on a
  one-stage prototype before scaling to 8+2 stages.
- **Interference false positives on touching faces.** Use `--epsilon 20` and
  the 20 mm³ joint-contact cap; declare only genuinely intended contacts in
  `ignore` and document each.
- **Loft twist geometry correctness.** Verify measured bbox/volume against a
  hand-computed reference for a known twisted triangle/airfoil before using it
  in the model; render each blade row in isolation.
- **Demo capture pipeline (studio dev server + ffmpeg).** Attempt via the
  repo's capture scripts; degrade gracefully to panel/render evidence if the
  environment blocks it.
