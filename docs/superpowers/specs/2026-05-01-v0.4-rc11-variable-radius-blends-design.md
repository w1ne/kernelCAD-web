# v0.4-rc11 Variable-Radius Fillet/Chamfer + Bundled Quality Fixes — Design

**Date:** 2026-05-01
**Milestone:** v0.13.0-rc.11 (NORTHSTAR roadmap step in v0.4-rc trajectory: variable-radius blends + close 4 rc.10 review findings)

## Why

Variable-radius fillets and chamfers are real CAD geometry agents currently can't reach. The existing `Shape.fillet(radius, edges)` applies one radius to all selected edges in a single call. A typical mechanical part has top working edges that want a small fillet (e.g. 0.5 mm — light deburring) and bottom mounting edges that want a larger fillet (e.g. 2 mm — ergonomic / fluid flow). Today the agent has to chain two fillets, where the second sees the geometry already changed by the first — different shape from the intended single-blend.

`Sketch.fillet([{edges, radius}, ...])` lets the agent specify per-group radii in one operation. Replicad's `RadiusConfig<R>` accepts a `(Edge) => R | null` function form precisely for this case.

Bundled with the feature: 4 rc.10 review findings.

## Scope

**Primary feature:** variable-radius fillet + chamfer parity

**Bundled fixes:** I-A + I-B + I-C + I-D

**Out of scope:**
- Closed-rail sweep — rc.12
- 3D path builder — rc.12+ (or never; agents have `helix()` + raw polylines)
- Text/embossing — rc.12+ (would activate dead `multi-face-profile` code path)
- Other rc.10 nits (N-1..N-10) — rc.12 quality pass

## API

```typescript
// Existing (rc.6+) — uniform radius. UNCHANGED.
shape.fillet(2, { atZ: 5 });

// NEW (rc.11) — variable. Distinguished by first-arg type (array vs number).
shape.fillet([
  { edges: { atZ: 5 }, radius: 2 },
  { edges: { atZ: 0 }, radius: 0.5 },
]);

// Same shape for chamfer.
shape.chamfer([
  { edges: { atZ: 5 }, distance: 1 },
  { edges: { atZ: 0 }, distance: 0.3 },
]);

// Mixed selectors per group: query for top, label for the rim.
shape.fillet([
  { edges: { atZ: 5 }, radius: 2 },
  { edges: { face: 'rim' }, radius: 1 },
]);

// Single-group array also valid (degenerate to uniform):
shape.fillet([{ edges: { atZ: 5 }, radius: 2 }]);

// Edges that don't match any group pass through unfilleted (opt-in semantics):
// box.fillet([{ edges: { atZ: 5 }, radius: 2 }]) — bottom + side edges stay sharp.
```

### Type signatures

```typescript
type FilletGroup = { edges: EdgeSelector; radius: number };
type ChamferGroup = { edges: EdgeSelector; distance: number };

class Shape {
  fillet(radius: number, edges?: EdgeSelector): Shape;
  fillet(groups: FilletGroup[]): Shape;

  chamfer(distance: number, edges?: EdgeSelector): Shape;
  chamfer(groups: ChamferGroup[]): Shape;
}
```

The capture-time dispatch uses `typeof radiusOrGroups === 'number'` to choose between the existing path and the new variable path. Array form requires every group to have a positive finite `radius` (or `distance`) — validated at lowering, surfacing as `feature.fillet.invalid-group` (or `feature.chamfer.invalid-group`).

### Validation

- Empty array → `feature.fillet.empty-groups` (or `feature.chamfer.empty-groups`)
- Group missing `edges` field → `feature.fillet.invalid-group`
- Group with non-finite or non-positive `radius` (or `distance`) → `feature.fillet.invalid-group`
- Replicad-thrown errors during fillet → existing `feature.fillet.failed` (catch-all unchanged)

### Diagnostic codes (4 new)

| Code | When | Hint |
|---|---|---|
| `feature.fillet.empty-groups` | Array form with `groups.length === 0` | "Variable-radius fillet needs at least one group. Pass `[{ edges: ..., radius: ... }, ...]` with one entry per intended blend region." |
| `feature.fillet.invalid-group` | Group has missing/invalid `edges` or non-finite/non-positive `radius` | "Each fillet group needs `edges` (an EdgeSelector or canonical face) and a positive finite `radius`. Check the failing entry's index in the diagnostic message." |
| `feature.chamfer.empty-groups` | Array form with `groups.length === 0` | "Variable-distance chamfer needs at least one group. Pass `[{ edges: ..., distance: ... }, ...]` with one entry per intended bevel region." |
| `feature.chamfer.invalid-group` | Group has missing/invalid `edges` or non-finite/non-positive `distance` | "Each chamfer group needs `edges` (an EdgeSelector or canonical face) and a positive finite `distance`." |

## Architecture

### Capture layer (`src/capture/proxy.ts`)

`Shape.fillet` and `Shape.chamfer` get the array overload. When the first arg is an array, capture goes down a new path:

```typescript
fillet(radiusOrGroups: number | FilletGroup[], edges?: EdgeSelector): Shape {
  if (typeof radiusOrGroups === 'number') {
    // Existing path — unchanged.
    return this.session.edgeFeature('fillet', this, 'radius', radiusOrGroups, edges);
  }
  // Variable-radius path: register a fillet record with metadata.groups.
  // Each group's `edges` field is converted to a FeatureRef via the same
  // helper buildEdgeFeatureRef that handles single-fillet selectors.
  return this.session.variableEdgeFeature('fillet', this, 'radius', radiusOrGroups);
}
```

`CaptureSession.variableEdgeFeature` is a new helper next to `edgeFeature`:

```typescript
variableEdgeFeature(
  kind: 'fillet' | 'chamfer',
  base: Shape,
  valueKey: 'radius' | 'distance',
  groups: Array<{ edges: EdgeSelector; [k: string]: number | EdgeSelector }>,
): Shape {
  if (!this.records.some(r => r.id === base.id)) {
    throw new Error(`${kind}: base shape '${base.id}' is not from this CaptureSession`);
  }
  const inputs: Record<string, FeatureRef> = {
    base: { kind: 'feature', id: base.id },
  };
  // Each group gets its own input slot edge_group_${i} so the lowerer can
  // resolve the EdgeRef per group (mirroring how loft uses sketch_${i}).
  const metadataGroups = groups.map((g, i) => {
    const ref = buildEdgeFeatureRef(base.id, g.edges);
    if (ref.key === 'edges') {
      inputs[`edge_group_${i}`] = ref.value;
    }
    return { radius: g[valueKey], hasFaceWrapper: ref.key === 'face' };
  });
  // ... params unchanged style; metadata carries groups + variable flag
}
```

### FeatureRecord shape

`'fillet'` and `'chamfer'` records get a new `metadata.variable: true` flag and `metadata.groups` array. When `variable: true`, the lowerer dispatches to a new `applyVariableFillet` (or `applyVariableChamfer`) helper. When absent (legacy path), existing single-radius lowerer code runs unchanged.

### Lowerer (`src/backends/occt/edgeSelection.ts` or new file)

New helper `applyVariableFillet(base, groups, recordsForLabelLookup)`:

1. For each group, resolve the EdgeRef to a list of `Edge` instances (reuse `resolveEdgesRef` / `pickFace` chains).
2. Build a `(e: Edge) => number | null` function that:
   - For each input edge, iterate group edge sets, return matching group's radius
   - Use `isSameEdge` (existing in `edgeQueries.ts`) for geometric matching
   - Return `null` if no group matches → Replicad leaves the edge sharp
3. Pass the function to Replicad's `shape.fillet(radiusConfig)`.

Same pattern for chamfer.

## Risks

- **`isSameEdge` heuristic** — used to map Replicad's `Edge` instances back to per-group sets. If two groups' edge sets accidentally overlap (agent error), the function-form returns the FIRST matching group's radius. Document in JSDoc that groups should be mutually exclusive; surface a `feature.fillet.overlapping-groups` warning if detected (cheap to compute via set-intersection test before applying).
- **Replicad function-form edge identity** — `(e: Edge) => number | null` receives an `Edge` instance from Replicad's iteration. Our pre-resolved sets came from `resolveEdgesRef`. If Replicad yields fresh Edge wrappers per call (the rc.6 indexOf bug pattern), the geometric `isSameEdge` matching is required (not reference equality). The existing `selectEdges` already uses this pattern; reuse the same helper.
- **Function vs filter Replicad dispatch** — Replicad's `RadiusConfig` also has an object form `{ filter: EdgeFinder, radius }`. We use the function form to support multiple radii in one call. Document the choice.
