# v0.4-rc.14 Quality Pass v4 — Design Spec

**Goal:** Close the rc.13 review punch list (1 Critical + 6 Important + 7 Nits) and harden the agent-facing surface against the drift class that produced C1.

**Architecture:** A pure quality milestone matching the rc.7/rc.9/rc.12 cadence. Twelve focused tasks. The dominant work is the SKILL.md overhaul (C1) — agents read SKILL.md as their primary handbook, and 4-5 milestones of drift have left it claiming `// v0.2-alpha`, missing `.mirror`/`.reflect`, and listing shipped capabilities under "Out of Scope." This milestone resets the document and adds the drift-sentinel coverage that prevents recurrence.

**Tech Stack:** TypeScript 5.9, Replicad 0.20.5, vitest 4. No new dependencies.

---

## Why this milestone

The rc.13 review surfaced one critical-class agent-first failure (SKILL.md is structurally stale) plus six bounded architectural / correctness fixes and seven nits. The Critical finding traces back to a pattern the review called out explicitly: **incomplete drift sentinels create false confidence.** rc.11's `serverInfo.version` sentinel guarded one column. rc.12's sweep regex was case-sensitive. rc.13's `skillToolCountDrift` sentinel catches MCP tool count but not Shape methods, Sketch methods, or diagnostic codes.

A pure quality milestone is the right home for the SKILL.md reset because:
1. It's structurally large (the doc spans 220+ lines and has ~5 stale sections to rewrite).
2. Bundling it with a feature would let "feature work" pressure compromise the doc quality.
3. The sentinel widening (N2 + new Shape/Sketch/code coverage) is the same pattern as the doc reset — both shore up the agent-facing surface.

The other findings (Vec3 overload deletion, transform validation, sketch upstream capture, hint accuracy, cast tightening, spec/plan sweep, sentinel actionable messages, kernelErrorToDiagnostic featureId, involution + composition tests) cluster naturally as "rc.13 review closure."

## Architecture decisions made before spec write-up

### A1 — SKILL.md overhaul is "aggressive reset," not "minimal patch"

**Decision.** Rewrite SKILL.md to match the current kernel state across all sections (Shape methods, Sketch methods, diagnostic codes, Out of Scope, sample scripts, version markers). Don't just add the missing `.mirror`/`.reflect` entries.

**Why.** The doc has drifted across rc.6 → rc.13 (sweep+loft+sketch builder+variable blends+mirror+reflect all shipped while SKILL.md kept saying "v0.2-alpha" and listing them as deferred). A minimal patch would leave the rest of the staleness in place and require another overhaul in rc.15+. Better to reset once and let the new drift sentinels (Component 2) catch future drift mechanically.

### A2 — Drift sentinel widening covers Shape, Sketch, and diagnostic codes (not just MCP tool count)

**Decision.** The existing `tests/unit/skill/skillToolCountDrift.test.ts` is extended (or split into siblings) to assert SKILL.md mentions every:
1. MCP tool name (existing, with the substring match tightened to word-boundary regex per N2)
2. `SHAPE_METHODS` entry (from `src/mcp/tools/listApi.ts`)
3. `SKETCH_METHODS` entry (from `src/mcp/tools/listApi.ts`)
4. Diagnostic code from the HINTS table (from `src/mcp/tools/whyDidThisFail.ts`)

**Why.** rc.13's sentinel only catches one drift dimension. The agent-first failure is structural — agents read SKILL.md as the canonical surface; if any column drifts, the agent's mental model diverges from the kernel.

### A3 — Vec3 mirror overload is fully deleted, not deprecated

**Decision.** Remove `OcctBackend.mirror(Vec3)`, `ShapeBackend.mirror(Vec3)`, `ShapeTransform`'s `op: 'mirror'` arm, and the lowerer's transform-loop `case 'mirror':`. Update the only test caller (`tests/unit/backends/occt/occtBackend.kind.test.ts:26`) to use `reflect` or remove if redundant.

**Why.** The review confirmed the overload is unreachable through any user-facing path — `Shape.mirror` creates a feature, not a transform; `Shape.reflect` creates an `op: 'reflect'` transform, not `op: 'mirror'`. Keeping dead code with hidden semantics is agent-hostile (agents reading the backend see two methods with the same name and different return shapes). Deletion is the cleanest fix.

### A4 — Transform-site validation matches the feature-site validation

**Decision.** The lowerer's `case 'reflect':` in the transform loop adds a `isValidPlaneSpec` guard before calling `OcctBackend.reflect(plane)`. If invalid, emit `feature.transform.invalid-plane` with `reachable: 'engine-path'`.

**Why.** The mirror feature path validates; the reflect transform path doesn't. Same input type, two paths, only one validates is an inconsistency that bugs hide in. The fix matches the existing pattern. The diagnostic is forward-looking (most agents will go through capture, which validates first), but covers direct-IR-construction paths (e.g. future MCP `add_feature` builders).

### A5 — `Sketch.reflect` captures upstream sketch as `inputs.source`

**Decision.** `Sketch.reflect(axis)` registers a new sketch FeatureRecord with `inputs.source: { kind: 'feature', id: <upstream-sketch-id> }` so `recompute.input.missing` cascades correctly when the upstream sketch fails to lower.

**Why.** Without this, an agent-side `why_did_this_fail` walker on a reflected sketch can't traverse to the source. Asymmetric with `Shape.mirror` which has `inputs.base`. The fix is a one-field addition to the capture-time call.

### A6 — N4 stripping: lineage refs leave repo files; sentinel prevents recurrence

**Decision.** Strip Fusion 360 / OpenSCAD references from rc.13 spec+plan. Add a sentinel test (`tests/unit/docs/specsCompetitorRefs.test.ts` or similar) that greps `docs/superpowers/specs/*.md` and `docs/superpowers/plans/*.md` for the broader competitor regex (case-insensitive, including `CATIA`, `NX`, `Fusion360` no-space, etc).

**Why.** rc.13's spec/plan committed lineage info that should have lived only in memory. The lineage memory at `~/.claude/projects/-home-andrii/memory/kernelcad_design_lineage.md` already captures the same content. Repo-side stays native; memory holds the comparator map. Sentinel makes the rule mechanically enforceable across all spec/plan files.

## Components (12 tasks)

Per task: file paths, what changes, plus the test it must produce or update. Plan-time work expands each into TDD steps.

### Component 1 — SKILL.md overhaul (closes C1, primary)

**Files:** `src/skill/SKILL.md`.

**Edits.**
1. **Header / version markers.** Remove all `// v0.2-alpha`, `// v0.4-alpha` etc from sample scripts. Update any "Currently shipping in <version>" claims to match `package.json`'s `version`.
2. **Shape methods section.** Add `.mirror(plane)`, `.reflect(plane)`. Verify every entry in `src/mcp/tools/listApi.ts` SHAPE_METHODS appears here. Match existing style.
3. **Sketch methods section.** Add `.reflect(axis)`. Verify every entry in `src/mcp/tools/listApi.ts` SKETCH_METHODS appears here.
4. **Diagnostic codes table.** Rewrite to include every code from `src/mcp/tools/whyDidThisFail.ts` HINTS. Group by family (`feature.fillet.*`, `feature.mirror.*`, `feature.sketch.*`, `recompute.*`, `cli.*`, `export.*`). Drop entries for codes that no longer exist.
5. **Out of Scope section.** Remove items that have shipped (lofts/sweeps shipped rc.10/rc.8; sketch builder shipped rc.6; variable blends shipped rc.11; mirror/reflect shipped rc.13). Keep only items that remain genuinely deferred.
6. **Sample scripts section.** Refresh to use current API. At least one sample showing variable-radius blend, one showing mirror, one showing the sketch builder + extrude pipeline.

**Style consistency.** Match the existing voice (terse, agent-targeted). Don't expand beyond what agents need.

### Component 2 — Drift sentinels (closes C1 secondary, N2)

**Files:**
- Modify: `tests/unit/skill/skillToolCountDrift.test.ts` — tighten substring match to word-boundary regex (closes N2).
- Create: `tests/unit/skill/skillShapeMethodsDrift.test.ts` — imports SHAPE_METHODS from `src/mcp/tools/listApi.ts`; asserts SKILL.md mentions each method name with word boundaries.
- Create: `tests/unit/skill/skillSketchMethodsDrift.test.ts` — same for SKETCH_METHODS.
- Create: `tests/unit/skill/skillDiagnosticCodesDrift.test.ts` — imports HINTS from `src/mcp/tools/whyDidThisFail.ts`; asserts SKILL.md's diagnostic-codes table mentions each code.

**Pattern.** Each new test reads SKILL.md as text, iterates the canonical source (TOOLS / SHAPE_METHODS / SKETCH_METHODS / HINTS keys), and asserts each name appears in SKILL.md within a code-fence or table cell. Use `\b<name>\b` word-boundary regex to avoid the substring false-positive class.

**Test.** New integration test:
```typescript
it('Sketch.reflect cascades upstream sketch failures via inputs.source', async () => {
  const code = `
    return path()
      .lineTo(1, 1)  // missing moveTo — upstream sketch fails to lower
      .close()
      .reflect('x')
      .extrude(1);
  `;
  const run = await runScript({ code, fileName: '<test>' });
  const engine = new RecomputeEngine(new OcctLowerer());
  const result = await engine.run(run.records);
  // The reflected sketch should NOT lower (upstream failed).
  // recompute.input.missing should fire on the reflected sketch.
  const codes = result.diagnostics.map(d => d.code);
  expect(codes).toContain('recompute.input.missing');
});
```

If kernelCAD's command structure includes float coordinates, `expect(twice.commands).toEqual(sketch.commands)` may fail on floating-point precision. Plan should pick a tolerance-aware comparison or verify that the reflection math is exact (it is, for cardinal axes; inexact only with offset forms involving subtraction).

3. **Component 9's sentinel test pattern.** The spec-file regex check is meta-recursive — this very rc.14 spec mentions "OpenSCAD" or similar names in its rationale text? Verify and either strip from the spec or document the allow-list pattern. Plan should resolve.
