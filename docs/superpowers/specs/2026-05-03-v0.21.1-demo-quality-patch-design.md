# v0.21.1 — demo-quality patch + browser fillet face-ref parity (design)

> **Status:** spec — awaiting plan + implementation.
> **Workstream:** v0.21.1, follow-up to [v0.21 synchronized live-build demos](./2026-05-03-v0.21-synchronized-live-build-demos-design.md).
> **Reframes:** v0.21.1 verifier work moves to v0.22 (separate workstream).

## Why

The v0.21 ship landed three known follow-ups that block calling the demo pipeline "promo-grade":

1. **`{ face: 'top' }` not lowered in browser worker.** The v01 shape proxy in `src/lib/v01ApiShim.ts` intercepts `subtract`/`union`/`translate`/`rotate` but lets `fillet`/`chamfer` fall through to Replicad's native method, which expects an `EdgeFinder` — not a `{ face: 'top' }` object. So `plate.subtract(hole).fillet(r, { face: 'top' })` silently mis-handles in the browser. The v0.2 retro demo had to fall back to `examples/bench/box-minus-divider.kcad.ts` (just `box.subtract(box)` — no fillet, doesn't show face tracking through booleans).

2. **Reveal order = OCCT iteration order.** `loadScript()` runs the whole script and produces a flat array of face meshes from the *final* shape. `revealFaces(count)` slices the next N off that array, so which faces fade in for "box_1's transition window" is essentially arbitrary — bears no relation to the feature graph.

3. **Color-flash transitions never fire.** `AnimationEngine.enqueue()` does `scene.getObjectByName(event.featureId)` looking for `box_1`, `boolean_1`, etc. — but the scene only contains `face-{gi}-{faceId}` meshes from `loadScript()`. The lookup returns undefined, so every `boolean.cut`/`modifier`/`boolean.fuse` branch early-returns. Only the reveal-fade actually runs.

**Root-cause grouping:** #2 and #3 share the same root cause — no per-feature mesh organization. Fix the loader to group meshes by feature ID, and both fall out. #1 is independent.

## Out of scope

- **Visual verifier loop** (`render_views`, `compare_to_intent`, VLM-critique). Originally tagged for v0.21.1 in the v0.21 design; reframed to **v0.22**.
- **Rotated/transformed canonical face refs in the browser worker.** The Node OCCT backend tracks faces through transforms via `findCanonicalFaceHash`; matching that in the browser worker requires per-face provenance (shape lineage tracking through Replicad ops). Out of v0.21.1 scope. Browser worker will throw a clear error when the user combines `rotate` + canonical face ref.
- **Per-feature face provenance for shells/drafts.** Current demos don't use these.
- **Sketch features in per-feature meshing.** Current demos don't return sketches as standalone features.

## K2 — extract `meshing.ts`

Move from `src/backends/occt/worker.ts` to a new `src/backends/occt/meshing.ts`:

- `meshFaceToGeometry(face, faceId): FaceGeometry | null` (currently lines ~377+).
- `meshShape(shape): GeometryResult` — wraps the per-shape loop (faces array → `FaceGeometry[]`, plus `volume` and `edges` extraction; lines ~600–663).
- Co-located helpers (`isRecord`, `getFn`, `tryExtractPlaneFromFace`, `tryExtractCylinderFromFace`, `tryGetVolume`, etc.) — meshing-only utilities move with them. Worker imports from the new module.

Worker behavior unchanged; precondition for K1 to reuse the same meshing.

## K1 — `src/capture/featureMeshing.ts`

```ts
export interface FeatureMesh {
  featureId: FeatureId;
  featureKind: FeatureKind;
  predecessors: FeatureId[];
  op?: 'subtract' | 'union' | 'intersect';   // populated for kind === 'boolean'
  faces: FaceGeometry[];
  volume?: number;
  edges?: Float32Array;
}

export interface Bounds {
  min: [number, number, number];
  max: [number, number, number];
}

export async function meshFeaturesPerFeature(
  records: readonly FeatureRecord[],
): Promise<{ features: FeatureMesh[]; bounds: Bounds }>;
```

Internally:

1. Construct an `OcctBackend` lowerer (already produces per-feature `ShapeBackend`).
2. Run `RecomputeEngine.run(records, { onEvent })`.
3. For each `feature.compiled` event, call `meshShape(event.shape)` from K2 → `FaceGeometry[]`.
4. Aggregate AABB across all features for camera fit.
5. For `kind === 'boolean'`, copy the `op` field from the FeatureRecord into the result.

Each entry is the feature's *own* shape (cylinder for `cylinder_1`, carved plate for `boolean_1`, filleted result for `fillet_1`). This matches AnimationEngine semantics: `add` reveals its own group; `boolean.cut` fades predecessor groups out as this feature's group fades in.

## D1 — DemoPlayer API change

`DemoPlayerWindow` becomes:

```ts
loadFeatureMeshes(
  perFeature: FeatureMeshSerialized[],
  bounds: Bounds,
): { groupCount: number };
```

Where `FeatureMeshSerialized` has typed-array fields converted to `number[]` for JSON transport over the Playwright bridge.

For each feature: build a `THREE.Group` with `group.name = featureId`, add to scene, populate with one `THREE.Mesh` per face (existing `MeshPhongMaterial`, `opacity: 0`, `transparent: true`). Center & camera-fit using supplied bounds (logic identical to today's `fitCameraToBounds`).

**Deleted:** `loadScript`, `revealFaces`, `RevealAnim`, `faceMeshesRef`, `nextRevealIdxRef`, `revealAnimsRef`. The reveal-fade lifecycle moves entirely into AnimationEngine (D2).

**Bridge serialization** (one helper, one place that knows about TypedArray ↔ JSON):

- `serializeForBridge(f: FeatureMesh): FeatureMeshSerialized` — `vertices`/`indices`/`normals`/`edges` become `number[]`; everything else passes through.
- Demo player rehydrates on receipt: `new Float32Array(arr)`, `new Uint32Array(arr)`. Co-located with `FeatureMeshSerialized` interface.
- Adds ~2× memory transiently during load; fine for current mesh sizes.

## D2 — AnimationEngine update

`enqueue(event)` swaps from "find one mesh" to "find one group, walk children":

```ts
const group = this.scene.getObjectByName(event.featureId) as THREE.Group | undefined;
if (!group) return Promise.resolve();
const meshes = group.children.filter((c): c is THREE.Mesh => c instanceof THREE.Mesh);
const mats = meshes.map((m) => m.material as THREE.MeshPhongMaterial);
```

Per-transition behavior (applied across **all** materials in the group, and predecessor groups for cut/fuse/modifier):

| Transition | Predecessor groups | This feature's group |
|---|---|---|
| **add** (box, cylinder, sphere, extrude, …) | — | All meshes: `opacity 0→1` ease-out 500ms, `scale 0.85→1.0` |
| **boolean.cut** | Cutter group: 0–150ms color flash to red `(1, 0.3, 0.3)`, then `opacity 1→0` over 250ms; target group: `opacity 1→0` over 250ms (replaced by carved result) | 0–150ms hidden, 150–400ms `opacity 0→1`, 400–600ms hold |
| **boolean.fuse** | All predecessor groups: 0–150ms yellow glow `(1, 0.9, 0.4)`, then `opacity 1→0` over 350ms | 150–500ms `opacity 0→1` ease-out |
| **modifier** (fillet, chamfer, shell, draft) | Predecessor group: `opacity 1→0` over 250ms (replaced by modified result) | 0–150ms cyan `(0.4, 0.9, 1)` flash, 150–400ms alpha-flash decay 0.7→1.0 |
| **transform** (mirror) | — | `opacity 0→1` ease-out 500ms |
| **fallback** | — | `opacity 0→1` 400ms (Tier-1 from v0.21 spec) |

**Behavior change vs. today:** predecessors fade out on cut/fuse/modifier (today they stay visible because no swap happens). This is the visual story for "my cutter became part of the result" — confirmed during brainstorming as intended look.

**Implementation notes:**

- Loop `for (const mat of mats)` and `for (const { mats, origs } of predGroups)`. Original-color tracking changes from `originalColor: THREE.Color` to `originalColors: THREE.Color[]` per group.
- `event.shape` no longer used by AnimationEngine for cut classification (today: `(event.shape as { __op?: string }).__op === 'subtract'`). Replaced by explicit `op` field on the wire event, populated Node-side from the FeatureRecord.
- `isFrameReady()` semantics unchanged: returns true when `active.length === 0`. Reveal/animation polling collapses to a single `await page.waitForFunction(() => window.__demoPlayer.isFrameReady())` after each `onEvent`.

## K3 — Browser worker face-ref support

In `src/lib/v01ApiShim.ts:wrap()`, after the existing `subtract`/`union`/`intersect` cases, add:

```ts
if (prop === 'fillet') return makeEdgeOp('fillet', t, meta);
if (prop === 'chamfer') return makeEdgeOp('chamfer', t, meta);
```

Where:

```ts
function makeEdgeOp(op: 'fillet' | 'chamfer', t: RawShape, meta: WrapMeta) {
  return (size: number, filter?: unknown) => {
    const finder = canonicalFaceFilterToFinder(t, filter, meta);
    const native = (t as Record<string, unknown>)[op] as (...args: unknown[]) => unknown;
    return wrap(native.call(t, size, finder ?? filter), meta);
  };
}
```

**`canonicalFaceFilterToFinder(shape, filter, meta)`** — new helper, ~40 LoC, returns `null` for non-canonical filters (passes through unchanged for callers using a real `EdgeFinder`):

1. Recognize `{ face: 'top' | 'bottom' | 'left' | 'right' | 'front' | 'back' }`. Anything else → return `null`.
2. If `meta.rotated === true`, **throw**: `"v01 shim: canonical face refs (e.g. { face: 'top' }) on rotated shapes are not supported in the browser worker yet — use the Node kernel for full v0.2 face tracking. Tracking deferred (v0.21.x follow-up)."`
3. Compute axis-aligned bounding box via Replicad's `boundingBox` (falls back to face-vertex iteration if not present).
4. Map face name → plane:
   - `top` → `('XY', maxZ)`, `bottom` → `('XY', minZ)`
   - `back` → `('XZ', maxY)`, `front` → `('XZ', minY)`
   - `right` → `('YZ', maxX)`, `left` → `('YZ', minX)`
5. Return `new replicad.EdgeFinder().inPlane(planeName, distance)` (Replicad default tolerance).

**Rotation tracking via `wrap()` meta.** `wrap()` gains a third arg `meta: WrapMeta = { rotated: false }`:

- `rotate` propagates `wrap(rotated, { ...meta, rotated: true })`.
- Booleans propagate `rotated` if any operand was rotated.
- `translate` does **not** set `rotated` (axis-aligned bbox still valid).

The throw is caught by the worker's `try/catch` and surfaces as an `ERROR` response — visible in live-editor diagnostics.

## D3 — captureDemo simplification

The reveal-driver loop (lines 215–248) collapses substantially. Replace:

```ts
// OLD
const loadResult = await page.evaluate(s => __demoPlayer.loadScript(s), loaded.source);
const facesPerEvent = Math.ceil(loadResult.faceCount / loaded.features.length);
// per-frame loop also calls revealFaces(facesPerEvent, durationMs) ...
```

With:

```ts
// NEW
const { meshFeaturesPerFeature } = await import('../src/capture/featureMeshing');
const { features, bounds } = await meshFeaturesPerFeature(loaded.features.map(f => f.record));
const serialized = features.map(serializeForBridge);
await page.evaluate(({ feats, b }) => __demoPlayer.loadFeatureMeshes(feats, b), { feats: serialized, b: bounds });
// per-frame loop: only emit onEvent (with the new `op` field for cuts) — no revealFaces call.
```

`--rotate-only` path also simplified: load meshes once, start rotate phase, no replay-and-advance needed.

## Risks & mitigations

| Risk | Mitigation |
|---|---|
| Node-side OCCT meshing produces visually different geometry from the browser Replicad path. | K2 extracts shared meshing helpers — both paths use identical face/edge extraction code. Backend lowering may still differ; mitigated by integration check (`capture-demo:retro-v0.1` must produce equivalent MP4). |
| `rotate` tracking via `wrap()` meta misses paths (e.g., shape obtained outside the proxy then rotated). | Initial scope: `wrap()` is the only entry; if a path bypasses it, the canonical-face filter computes wrong but doesn't crash. Test (c) explicitly covers the rotated case to lock in the throw. |
| Demo player bridge JSON serialization is too large for big meshes. | Current demos: < 100 faces total. Hard cap not anticipated in v0.21.1 scope. If hit later, switch to `page.evaluate` with binary-string encoding or expose a transferable-buffer worker channel. |
| Boolean.cut "fade out predecessors" looks worse than today's "predecessors stay visible". | Visually confirmed during brainstorming as the intended story. R2 visual smoke check is the gate; if it looks wrong, fix in same PR. |
