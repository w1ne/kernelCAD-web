# v0.21 — Synchronized live-build demo automation — Design

> **Workstream #21** of the [v0.2-to-v1.0 gap-closure roadmap](./2026-05-03-v0.2-to-v1.0-gap-closure-roadmap-design.md). Originally scoped as "Visual verifier loop"; demo automation prioritized first per user direction. Visual verifier (`render_views` + `compare_to_intent` + VLM-critique loop) deferred to a v0.21.1 follow-up workstream.

**Goal:** Ship a replay-based capture pipeline that produces promo-grade ≤30s MP4 videos showing the agent live-building a CAD part, animated synchronously with terminal output, on every per-module ship — unblocking H11 enforcement.

**Architecture:** Two-phase pipeline. Phase 1 (existing) — eval harness produces `output.kcad.ts` + transcript + score. Phase 2 (new) — `scripts/captureDemo.ts` replays the script through a feature-event-emitting kernel into a dedicated `/demo-player` route running in Playwright headless Chromium, animates each feature via Tier-2 kind-specific transitions, captures 30fps screenshots, stitches via ffmpeg, composes a static H11 panel via sharp.

**Tech Stack:** TypeScript, Vite (existing), Playwright + Chromium (existing), three.js 0.182 (existing), `sharp` (new — static-panel composer), `shiki` (new — code highlighting), `ffmpeg` (system binary, detected at runtime).

---

## Why this milestone

H11 of the gap-closure roadmap mandates a committed visual artifact set per per-module ship (`v0.X.0`) and per coverage gate. Today there is no toolset to produce this artifact. v0.2.0 cannot be tagged until the artifact lands. v0.1.0 was tagged without one (technical debt flagged in the G0 reevaluation).

User direction (memory: `feedback_kernelcad_demos_promo_video.md`) is that demos must be promo-grade MP4 video with a synchronized live-build narrative — terminal-and-viewer split-screen where every agent action animates the matching visual change in real time, followed by a showcase rotate phase. These artifacts are the public face of every shipped capability and feed promotional content directly.

The original H11 wording specified "≤30s GIF or MP4 ... terminal-on-left + 3D render-on-right side-by-side. Captured during a real harness run, not staged." That is amended by this spec (see §H11 amendment below) to: replay-based MP4-only, animated transitions per feature, controlled pacing.

## Goals

1. **Demo automation that actually runs.** `scripts/captureDemo.ts` replaces the existing stub, takes a corpus task or example script, produces a complete demo set (`demo.mp4` + `panel.png` + `whats-new.md` + metadata) under `docs/demos/v0.X/<task-id>/`.
2. **Three demo sets land in this PR.** v0.21 hero (`bracket-holes`), v0.1.0 retro (`bracket-with-hole`), v0.2.0 retro (`subtract-then-fillet-rim`).
3. **Per-module ship-gate enforcement.** A new `scripts/lint-demos.ts` fails CI on `v0.X.0` tag push when the corresponding `docs/demos/v0.X/` directory is empty or contains a `whats-new.md` with an unfilled `TODO:` marker.
4. **H11 amended in the same PR** so the spec wording matches what shipped.
5. **Re-runnable.** Re-running captureDemo on the same input produces equivalent output (deterministic pacing); `--rotate-only` re-renders just the rotate phase from cached metadata in ~3s for ffmpeg/animation tweaks.
6. **Foundation for v0.21.1 verifier follow-up.** The kernel-side feature-event stream landed here is the same surface the verifier will subscribe to for per-iteration intent comparison. No re-architecture.

## Anchors carried forward

- **Agent-first / MCP-native:** Phase 1 is the existing eval harness driving the agent through MCP. No demo-specific code path inside the agent loop. Demo capture runs *after* the agent — the MCP surface stays clean for agents.
- **AST-edit primacy:** The script being typed in the terminal pane is the AST-equivalent `.kcad.ts` source — the same artifact agents produce and consume. No transcript-formatted-for-demos divergence.
- **Diagnostic rigor:** Replay surfaces kernel diagnostics in the terminal pane (existing transcript already contains them); failed features render as `feature.failed` events with red-highlight flash before the run aborts.
- **Open:** All produced artifacts (MP4, PNG, MD) are committed to the public repo under `docs/demos/v0.X/`; reproduction commands are in `docs/demos/README.md`.

## Non-goals (explicit)

1. **No VLM-based visual verification.** `compare_to_intent` MCP tool, vision-language model critique, repair-on-disagreement orchestration → all deferred to v0.21.1 follow-up.
2. **No `render_views` MCP tool.** The verifier follow-up needs a 4-up ortho render shape; this PR only needs the hero-frame screenshot from the demo player. Premature MCP surface avoided.
3. **No `kernelcad capture` CLI command.** Workstream #10 (v0.11 finish) owns CLI extras (`render`, `capture`); this PR keeps demo capture as `scripts/captureDemo.ts` (an internal Node script). v0.11 will absorb captureDemo as a library when that workstream runs.
4. **No 9:16 vertical or 1:1 square output variants.** 16:9 only. Re-cropping to 1:1 is one-line ffmpeg if user wants a feed-format derivative later.
5. **No mesh-vertex morphing between feature states.** Tier-2 stylized transitions per feature kind only (scale-from-origin / cutter-fade / glow-flash / pose-interpolation). Geometry-correspondence morphing is out of any reasonable budget and not visibly required.
6. **No audio.** Silent MP4. Revisit if user starts posting to TikTok/Reels.
7. **No CI re-rendering of demos.** Demos are committed as ground truth; CI lint verifies presence + shape + non-TODO content, not pixel content.

## Architecture (high-level)

Two-phase pipeline:

**Phase 1 — Agent run (existing, unchanged):** `npm run eval -- --task <task-id>` produces `eval/runs/<run-id>/<task-id>/{output.kcad.ts, transcript.md, score.json}`. For retro-demos (v0.1, v0.2), Phase 1 is replaced by reading an existing `examples/*.kcad.ts` and a curated hand-written prompt under `scripts/demo-prompts/`.

**Phase 2 — Replay-based capture (new):** `scripts/captureDemo.ts` takes a Phase-1 output (or static script + prompt), spawns Vite + Playwright headless Chromium, opens `/demo-player?runDir=<path>&aspect=16x9`, replays the script through a feature-event-emitting kernel via Playwright `page.evaluate`, captures per-frame screenshots at 30fps, streams to ffmpeg, runs the static-panel composer, emits the `whats-new.md` template.

```
eval/runner.ts (Phase 1) ──> eval/runs/<run-id>/<task-id>/{output.kcad.ts, transcript.md, score.json}
                                                ▼
                                  scripts/captureDemo.ts
                                                ▼
                ┌───────────────────┬───────────┴──────────┬─────────────────────────┐
                ▼                   ▼                       ▼                         ▼
           ffmpeg + frames     Vite dev server      Headless Chromium            Static panel
           (30fps stream)      (existing)           /demo-player route           composer (sharp)
                ▼                                            ▲                         ▼
        <task>/demo.mp4                          feature events via Playwright `page.evaluate`   <task>/panel.png
                                                  (driven by replay loop)
```

## Components

### 1. Feature-event stream (`src/compute/featureEvents.ts` + recompute engine modification)

```ts
export type FeatureEvent =
  | { kind: 'feature.compiled'; featureId: FeatureId; featureKind: FeatureKind;
      shape: ShapeBackend; predecessors: FeatureId[];
      diagnostics: CompilerDiagnostic[]; health: 'healthy'|'warning' }
  | { kind: 'feature.failed'; featureId: FeatureId; featureKind: FeatureKind;
      predecessors: FeatureId[]; diagnostics: CompilerDiagnostic[] }
  | { kind: 'recompute.complete'; featureCount: number };

export type FeatureEventSink = (event: FeatureEvent) => void;
```

`RecomputeEngine.run()` (`src/compute/recomputeEngine.ts:17`) gains optional 2nd arg `{ onEvent?: FeatureEventSink }`. Inside the topo loop (existing lines 37–89), after each successful lower we emit `feature.compiled`; on failure, `feature.failed`. Transport-agnostic: in-process sink for the captureDemo orchestrator's dry-run validation pass; in-memory sink for unit tests; the demo-player page receives events via Playwright's `page.evaluate` from the orchestrator (no separate event transport).

The same surface is what the v0.21.1 verifier follow-up will subscribe to for per-iteration intent comparison.

### 2. `/demo-player` route (`src/components/demoPlayer/`)

Files:
- `DemoPlayerPage.tsx` — route entry; wires sub-components; exposes the `window.__demoPlayer` driver API for Playwright `page.evaluate`.
- `ViewerPane.tsx` — wraps existing `ParametricLayer` (`src/components/viewer/layers/ParametricLayer.tsx`) sized to viewer half of canvas; no app chrome.
- `TerminalPane.tsx` — typewriter-style script display, monospace JetBrains Mono, shiki-syntax-highlighted; types each statement at 80 chars/sec floor (faster if needed to fit timeline).
- `CameraController.ts` — eased camera nudges per feature event (300ms concurrent with first 300ms of transition); rotate-phase orbit driver.
- `Watermark.tsx` — bottom-right of viewer pane: "kernelCAD v0.X" JetBrains Mono 14pt white 60% alpha.

URL params: `runDir`, `aspect=16x9`, optional `pacingPath`, optional `titleCardSvg`. Page exposes `window.__demoPlayer` with `{ isFrameReady(): boolean; onEvent(e: FeatureEvent): void; setRotatePhase(durationMs: number): void }` for Playwright drive via `page.evaluate`. No WebSocket / no separate transport — captureDemo orchestrator pushes events directly via Playwright's serialized page-evaluate channel.

Mounted at `/demo-player`. Route added to existing router.

### 3. Animation engine (`src/components/demoPlayer/AnimationEngine.ts`)

Hand-rolled RAF-based tweening (no new dep — three.js@0.182 only). Five Tier-2 transition types mapped from `FeatureKind`:

| Transition | Duration | FeatureKind values | Visual |
|---|---|---|---|
| **add** | 500ms | `box, cylinder, sphere, torus, extrude, revolve, loft, sweep, importedMesh, importedStep` | scale 0.85→1.0 + opacity 0→1, ease-out |
| **boolean.cut** | 600ms | `boolean` (op=subtract), `hole`, `cut` | predecessor cutter mesh red-tint flash 150ms → fades opacity 1→0 over 250ms while carved result fades 0→1 over same 250ms |
| **boolean.fuse** | 500ms | `boolean` (op=union\|intersect) | predecessor meshes glow yellow-tint 150ms → unified mesh fades 0→1 over 350ms (ease-out) |
| **modifier** | 400ms | `fillet, chamfer, shell, draft` | affected edges/faces glow cyan 150ms → mesh swap with brief alpha-flash 250ms |
| **transform** | 500ms | `mirror` (only kernel transform feature today; v0.3 will add translate/rotate/scale) | eased pose interpolation |
| **sketch** | 500ms | `sketch, constrainedSketch` | **Tier 1 fallback for v0.21** — uniform fade-in 0→1 over 400ms; Tier 3 stroke-reveal deferred |
| **fallback (Tier 1)** | 400ms | `assemblyPart, assemblyJoint, assemblyConnect, sheetMetal, sdf` | uniform scale 0.9→1.0 + fade-in (these features ship in later workstreams; per-module workstream is responsible for registering its own Tier-2 transition or accepting Tier-1 fallback as defined in the per-module ship-gate addendum) |

`AnimationEngine.enqueue(event)` returns a Promise resolving when that feature's transition is settled. `window.__demoPlayer.isFrameReady()` returns `true` when the in-flight queue is empty.

For `boolean.cut`, the engine retains the upstream cutter mesh for one transition window (looked up via `predecessors` in the event) before fade-out. The unmodified ParametricLayer mesh dictionary is the source of truth; AnimationEngine layers visual state (opacity, scale, tint) via three.js material/transform manipulation.

### 4. Pacing engine (`scripts/lib/pacingEngine.ts`)

```ts
interface FeatureTimeline { startAtMs: number; durationMs: number; pauseMsAfter: number; cameraNudgeMs: number; }
interface Pacing {
  features: Map<FeatureId, FeatureTimeline>;
  preRollMs: number;          // 0 for normal, 2000 for short-build title card
  rotateStartMs: number;
  rotateDurationMs: number;
  totalDurationMs: number;
}

function computeTimeline(features: FeatureRecord[], opts: PacingOpts): Pacing
```

**Default pacing rules:**

- Per-feature: `transitionMs(kind) + 800ms pauseMsAfter + 300ms cameraNudgeMs` ≈ 1.6s/feature
- Project total: `Σ per-feature + 8000ms rotate + 2000ms buffer`
- **If projected total > 30000ms** (build > 22000ms): shrink `pauseMsAfter` to 200ms; recompute. If still > 30000ms after pause-floor: shrink `cameraNudgeMs` to 100ms. If still > 30000ms: emit warning, truncate to first N features that fit + log "needs --pacing override".
- **If projected total < 12000ms** (build < 4000ms): extend `rotateDurationMs` to 12000ms, set `preRollMs=2000` for title card.
- Animation `transitionMs` from the registry NEVER compresses — these are the visible beats.

**`--pacing <override.json>` schema** (per-feature opt-in for hand-tuned promo cuts):

```json
{
  "features": {
    "box-1": { "pauseMsAfterOverride": 1500 },
    "boolean-3": { "transitionMsOverride": 800 }
  },
  "rotateMsOverride": 10000,
  "preRollMsOverride": 2000
}
```

### 5. captureDemo orchestrator (`scripts/captureDemo.ts` — replace stub)

```bash
npx tsx scripts/captureDemo.ts \
  --task <task-id-or-path> \
  --module v0.X \
  --output docs/demos/v0.X/<task-id>/ \
  [--script <path>] [--prompt <path>] [--pacing <override.json>] \
  [--title-card-svg <path>] [--rotate-only]
```

**npm script bindings** (added to `package.json`):

```json
"capture-demo": "npx tsx scripts/captureDemo.ts",
"capture-demo:hero": "npx tsx scripts/captureDemo.ts --task bracket-holes --module v0.21 --output docs/demos/v0.21/bracket-holes/",
"capture-demo:retro-v0.1": "npx tsx scripts/captureDemo.ts --script examples/bracket-with-hole.kcad.ts --prompt scripts/demo-prompts/v0.1-bracket.md --module v0.1 --output docs/demos/v0.1/bracket-with-hole/",
"capture-demo:retro-v0.2": "npx tsx scripts/captureDemo.ts --task subtract-then-fillet-rim --module v0.2 --output docs/demos/v0.2/subtract-then-fillet-rim/"
```

**Flow:**

1. Parse args. If `--task <id>`: read `eval/runs/<latest>/<id>/{output.kcad.ts, transcript.md, score.json}`. If `--script + --prompt`: read static example. Either form produces identical downstream outputs.
2. Parse script into topo-ordered feature list (re-uses `src/script-runtime/runScript.ts` to lower the script + the existing `RecomputeEngine` to validate executability — but in dry-run mode, no event emission yet).
3. Compute timeline via `pacingEngine.computeTimeline` with optional `--pacing` override.
4. Boot Vite dev server (or attach to `http://127.0.0.1:5173` if `reuseExistingServer` is up — same convention as `playwright.config.ts:31`).
5. Boot Playwright headless Chromium, set viewport to 1920×1080, open `/demo-player?runDir=<run>&aspect=16x9`. Wait for `window.__demoPlayer` to be defined before proceeding.
6. Render title card (if `preRollMs > 0`): fetch SVG → screenshot → push 60 duplicated frames (2s @ 30fps) to ffmpeg.
7. Run replay loop: drive feature events on schedule via Playwright `page.evaluate`. Per ~33ms: `await page.evaluate(() => window.__demoPlayer.isFrameReady())` → if ready, `page.screenshot({ type: 'png' })` → push buffer to ffmpeg stdin. If not ready, skip frame (ffmpeg `-vsync cfr -r 30` will duplicate the previous frame).
8. After last feature: hold for `pauseMsAfter` of last feature, then call `window.__demoPlayer.setRotatePhase(rotateDurationMs)`; capture rotate frames at 30fps.
9. Close ffmpeg stdin, await final encode. Validate output: file exists, size ≥ 1MB, ffprobe duration in `[10s, 30s]`.
10. Capture `hero-frame.png` via final-state `page.screenshot()`.
11. Run static-panel composer. Emit `whats-new.md` template + `meta.json` + `pacing.json` (debug aid for re-renders).

**`--rotate-only` mode:** Skips Phase 1 and the build-phase capture (no per-frame screenshots during build). Replays the script through the kernel silently to reconstruct final scene state in the demo-player, then runs only steps 8–10 (rotate phase capture + finalize). ~3s per re-render. Used when ffmpeg encoding params or rotate curve change. Reads `pacing.json` from the existing output directory for `rotateDurationMs` consistency.

### 6. Static-panel + whats-new generators (`scripts/lib/staticPanel.ts`)

`sharp`-based 4-quadrant compositor. Inputs:
- **Top-left:** prompt text rendered to PNG (plain monospace JetBrains Mono on neutral background via headless-Chromium screenshot of a styled HTML template; reuses booted Chromium from captureDemo). No markdown rendering — prompts display as-typed for fidelity.
- **Top-right:** `output.kcad.ts` syntax-highlighted via `shiki` → SVG → PNG.
- **Bottom-left:** `hero-frame.png` (final settled frame from captureDemo).
- **Bottom-right:** score badge — rendered from `score.json` (large pass/fail glyph + numeric score + per-criterion checklist).

Output: `<task>-panel.png`, 1920×1080, written to `docs/demos/v0.X/<task-id>/panel.png`.

`whats-new.md` written from template:

```markdown
# v0.X — <module-name>

<!-- TODO: 1-paragraph capability gain blurb in plain English. Replace this comment + the line below before merging. -->

This release adds <capability>. Demonstrated by the agent building <part-name> using <new-feature-list>.

![Demo](./demo.mp4)
![Panel](./panel.png)
```

### 7. CI lint (`scripts/lint-demos.ts`)

Runs only on `v*.*.*` tag push (not on develop/PR). Checks for the corresponding `v0.X.0` tag:

1. `docs/demos/v0.X/` exists and contains at least one subdirectory.
2. That subdirectory contains all of: `demo.mp4`, `panel.png`, `whats-new.md`, `meta.json`.
3. `whats-new.md` does NOT contain the literal string `TODO:` (forces fill-in before tag).
4. `demo.mp4` ffprobe duration is in `[10s, 30s]`.
5. `meta.json` parses and contains `gitSha`, `capturedAt`, `taskId` keys.

Failure exits non-zero, blocks the tag push (CI workflow gates the release on lint-demos pass).

## Output format

- **Resolution:** 1920×1080.
- **Aspect:** 16:9.
- **Frame rate:** 30fps.
- **Codec:** H.264 (`libx264`), `-crf 23 -preset slow -pix_fmt yuv420p -movflags +faststart`.
- **Length:** ≤30s. Layout: optional 2s pre-roll title card → variable build phase → 8s rotate phase → buffer.
- **Audio:** none (silent).
- **Watermark:** "kernelCAD v0.X" JetBrains Mono 14pt white 60% alpha, bottom-right of viewer pane only, full duration.
- **Title card** (only when `build < 4s`): 1920×1080 black background; "kernelCAD" wordmark JetBrains Mono 24pt white top-left; "v0.X — <Module name>" JetBrains Mono 56pt white centered; tagline JetBrains Mono 28pt gray below; fade-in 200ms / hold 1.6s / fade-out 200ms.
- **File-size target:** 6–15 MB per demo. Hard ceiling 50 MB triggers controller decision (LFS or recompress).
- **Storage:** committed to git directly under `docs/demos/v0.X/<task-id>/`. No LFS unless total demo set exceeds 50 MB.

## Risks (ranked)

1. **🟠 Playwright Chromium WebGL flakiness in CI.** Existing tests run with `workers: 1` for stability; demos add ~30s GPU-heavy work per task. **Mitigation:** capture runs locally only (excluded from `qc:full`); committed artifacts are ground truth; CI lint just verifies presence + shape, doesn't re-render.

2. **🟠 Replay drift from live agent.** Script extracted from agent transcript may not parse cleanly into ordered features for the replay (dynamic JS evaluation). **Mitigation:** replay reuses existing `runScript.ts` (`src/script-runtime/`) which already handles transpilation + isolation; we layer event emission on top, not parallel.

3. **🟡 ffmpeg install path.** Required system binary, not npm. **Mitigation:** detect at script start (`which ffmpeg`); friendly error with apt/brew/winget commands. CI runners (GitHub Actions ubuntu-latest) ship with ffmpeg.

4. **🟡 Boolean-cut transition realism.** "Cutter mesh briefly visible" requires keeping the predecessor cutter input shape alive past the boolean event for one transition window. **Mitigation:** AnimationEngine retains last-known cutter mesh per upstream-input lookup; v0.3 (when transform features land with their own meshes) may need re-tuning.

5. **🟡 File size budget.** 30s 1920×1080 30fps H.264 typically lands at 6–15 MB with `-crf 23 -preset slow`. **Mitigation:** lock encoding params; commit binaries directly; revisit LFS if total demo set exceeds 50 MB across all v0.X.

6. **🟢 Animation engine handles future feature kinds.** New kinds (assembly, sheetMetal, sdf) ship in later workstreams; AnimationEngine falls through to Tier-1 fade-in until those workstreams add their own transitions. Documented in the per-module ship-gate addendum.

7. **🟢 v0.21.1 verifier follow-up couples on event stream.** If verifier later wants `compare_to_intent` to use the same feature-event stream (e.g., per-feature critique vs. final-state-only), the interface is already shaped to support multiple sinks. No re-architecture expected.

## Open questions / explicit deferrals

- **`whats-new.md` ownership:** controller fills the TODO blurb manually before tag; not auto-generated. CI lint forces fill-in.
- **Demo refresh cadence:** demos for v0.1 and v0.2 are committed as snapshots from this PR. If kernel API changes break replay, the controller re-runs `npm run capture-demo:retro-v0.X` and commits fresh outputs. No automated drift detection.
- **Per-PR demo re-render:** out of scope. Only per-module ship requires demo. Mid-PR experimentation can render locally and discard.
