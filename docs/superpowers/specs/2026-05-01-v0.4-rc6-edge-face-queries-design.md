# v0.4-rc6 Query-First Edge/Face Selection — Design

**Date:** 2026-05-01
**Milestone:** v0.13.0-rc.6 (NORTHSTAR roadmap step in v0.4-rc trajectory: agent-introspectable edge/face selection)

## Why query-first (not label-only)

Agents drive kernelCAD through code generation. They target edges and faces on shapes whose origin they don't always control: imported STEP files, boolean results, transformed primitives, and shapes the user already had on disk. Capture-time labels alone don't reach those cases — labels exist only on shapes the agent built itself in the current script.

The query mechanism is **geometric** — it asks "find edges at Z=5", "find faces parallel to XY", "find vertical edges". It works on any shape regardless of provenance because the query operates on the OCCT BREP directly. The kernel (Replicad) already exposes the primitive (`EdgeFinder` / `FaceFinder`); rc.6 surfaces it through a stable, agent-friendly TypeScript API and adds three MCP introspection tools so agents can see what they'd target before running an operation.

Labels still ship in rc.6 — as ergonomic sugar that resolves through the same query path under the hood. Agents who prefer named segments get readable scripts; the kernel runs one resolver.

## Goals

1. Agents can target edges/faces on **any** shape via geometric queries (`atZ`, `parallel`, `convex`, `ofCurveType`, etc).
2. Agents can introspect any shape via three new MCP read tools to discover available edges/faces and their geometry before running fillet/chamfer/shell.
3. `path()...lineTo(x,y).label('rim')...extrude(d).fillet(r, { face: 'rim' })` works as ergonomic sugar.
4. The existing canonical face refs (`{ face: 'top' }` on box/cylinder/sphere) keep working unchanged.
5. All resolution paths converge on a single resolver — no duplicate codepaths.

## Non-goals (deferred)

- `coalesceEdges()` — collinear-segment merge (rc.7)
- Per-edge variable radius (`fillet([{edge, r:1}, {edge, r:2}])`) — rc.7
- Custom JS predicate `{ predicate: (e) => ... }` — agent-hostile, MCP can't introspect functions
- Labels on revolve — needs different probe-point strategy for axisymmetric faces (rc.7)
- Persistent topological IDs across booleans/transforms — separate "named topology" problem, v0.5+
- Set ops on selections (`union`/`intersection`/`subtract` of edge/face sets) — rc.7+

## API

```typescript
// Inline query (most common)
shape.fillet(2, { atZ: 5 })
shape.fillet(1.5, { atZ: 5, convex: true })
shape.fillet(2, { parallel: [0, 0, 1] })
shape.fillet(2, { ofCurveType: 'CIRCLE' })
shape.shell(0.5, { face: { atZ: 5 } })

// Composed queries — multiple keys are AND-combined
shape.fillet(2, { atZ: 5, parallel: [1, 0, 0] })

// Pre-select for compose / reuse
const verticalEdges = selectEdges(shape, { parallel: [0, 0, 1] });
shape.fillet(2, verticalEdges)

// Single-edge selector (throws if 0 or >1 match)
const bottomEdge = selectEdge(shape, { near: [25, 0, 0], atZ: 0 });
shape.chamfer(1.5, bottomEdge)

// Label sugar — resolves through the same query path
path()
  .moveTo(0, 0)
  .lineTo(20, 0).label('bottom')
  .lineTo(20, 5).label('right')
  .lineTo(0, 5).label('top')
  .close()
  .extrude(3)
  .fillet(1, { face: 'top' });   // string → look up label → translate to query

// Existing canonical refs keep working
box(10, 10, 5).fillet(1, { face: 'top' });   // 'top' is canonical for box
```

### `EdgeQuery` type

| Field | Type | Behavior |
|---|---|---|
| `atZ?` | `number` | Edge midpoint Z within `tolerance` |
| `atX?`, `atY?` | `number` | Same for X / Y axes |
| `near?` | `[x,y,z]` | Edges close to point; results sorted closest-first |
| `within?` | `BoundingRegion` | Edges fully inside a 3D box |
| `parallel?` | `[x,y,z]` | Edge direction parallel to vector |
| `perpendicular?` | `[x,y,z]` | Edge direction perpendicular to vector |
| `convex?` | `boolean` | Convex (outside-corner) edges |
| `concave?` | `boolean` | Concave (inside-corner) edges |
| `minAngle?` | `number` | Minimum dihedral angle (degrees) |
| `maxAngle?` | `number` | Maximum dihedral angle (degrees) |
| `ofCurveType?` | `'LINE' \| 'CIRCLE' \| 'BSPLINE'` | Edge curve type |
| `tolerance?` | `number` | Position tolerance, default 1.0 |
| `angleTolerance?` | `number` | Angular tolerance in degrees, default 10 |

`BoundingRegion` = `{ xMin?: number; xMax?: number; yMin?: number; yMax?: number; zMin?: number; zMax?: number }`.

### `FaceQuery` type

| Field | Type | Behavior |
|---|---|---|
| `atZ?`, `atX?`, `atY?` | `number` | Face centroid coordinate match |
| `parallelTo?` | `'XY' \| 'YZ' \| 'XZ' \| [x,y,z]` | Face normal parallel direction |
| `inPlane?` | `'XY' \| 'YZ' \| 'XZ'` | Face lies in a plane |
| `ofSurfaceType?` | `'PLANE' \| 'CYLINDER' \| 'SPHERE' \| 'CONE' \| 'TORUS' \| 'BSPLINE'` | Face geometric type |
| `containsPoint?` | `[x,y,z]` | Face contains the point |
| `near?` | `[x,y,z]` | Sorted closest centroid first |
| `tolerance?` | `number` | Default 1.0 |

### `EdgeSelector` (the type accepted by `fillet`/`chamfer`/`shell` arg-2)

```typescript
type EdgeSelector =
  | EdgeQuery                    // inline query — resolved at lowering time
  | EdgeSegment                  // pre-selected from selectEdges (single)
  | EdgeSegment[]                // pre-selected (multi)
  | { face: CanonicalFace }      // existing canonical face on box/cylinder/sphere
  | { face: string }             // canonical fallthrough or label lookup
  | undefined;                   // all sharp edges (existing behavior)
```

### `EdgeSegment` (returned by `selectEdges` and `list_edges`)

```typescript
type EdgeSegment = {
  id: string;                    // stable index within this shape lowering
  midpoint: [number, number, number];
  direction: [number, number, number];
  length: number;
  curveType: 'LINE' | 'CIRCLE' | 'BSPLINE' | string;
  convex: boolean | null;        // null for boundary edges
  dihedralAngleDeg: number | null;
  normalA: [number, number, number] | null;
  normalB: [number, number, number] | null;
  boundary: boolean;
};
```

## Architecture

### Capture layer

`Shape.fillet/chamfer/shell` arg-2 type widens to `EdgeSelector` (see above). At capture, the selector is stored verbatim on the FeatureRecord — resolution is deferred to lowering.

`PathBuilder.label(name: string): PathBuilder` mutates the most recent segment:

```typescript
label(name: string): PathBuilder {
  const last = this.commands[this.commands.length - 1];
  if (!last || last.kind === 'moveTo' || last.kind === 'close') {
    throw new Error('label() must follow a segment, not moveTo or close');
  }
  if (this.commands.some(c => c !== last && 'label' in c && c.label === name)) {
    throw new Error(`label('${name}') is already used in this sketch`);
  }
  (last as { label?: string }).label = name;
  return this;
}
```

`SketchCommand` union widens — every segment variant gets `label?: string`.

### Backend resolver (`src/backends/occt/edgeSelection.ts`)

Three new functions, all building on the kernel's existing `EdgeFinder` / `FaceFinder` primitives:

```typescript
resolveEdgeQuery(base: OcctBackend, query: EdgeQuery): Edge[]
resolveFaceQuery(base: OcctBackend, query: FaceQuery): Face[]
selectEdges(base: OcctBackend, query?: EdgeQuery): EdgeSegment[]
selectEdge(base: OcctBackend, query: EdgeQuery): EdgeSegment   // throws if 0 or >1
```

Each maps the typed query keys to kernel finder filters where available, then applies remaining filters (convex/concave/dihedral) directly on the resulting edge list. This keeps the implementation thin — most filtering is delegated to the kernel.

### Lowerer dispatch (`src/backends/occt/occtLowerer.ts`)

Existing `fillet/chamfer/shell` arms get extended dispatch on `EdgeSelector`:

1. `undefined` → all sharp edges (existing behavior)
2. `{ face: <canonical> }` on box/cylinder/sphere → existing canonical resolution (existing behavior)
3. `{ face: <string-name> }` and string isn't canonical → walk upstream sketch's `metadata.commands`, find the segment with matching `label`, build a probe-point query, hand to `resolveEdgeQuery`
4. Inline `EdgeQuery` → `resolveEdgeQuery` directly
5. `EdgeSegment` / `EdgeSegment[]` → resolve segment IDs back to `Edge` objects on the lowered shape, use directly
6. Empty result → `feature.edge-feature.no-edges-match` diagnostic

### Label-to-query translation

When `fillet(2, { face: 'rim' })` runs on a sketch-extrude:
- Lowerer reads upstream sketch's `metadata.commands`
- Finds segment with `label === 'rim'` and notes its endpoints
- For straight segment: probe = midpoint of the segment, lifted to z = depth/2
- Builds `EdgeQuery` = `{ near: probe, ofCurveType: 'LINE', tolerance: 0.5 }`
- Hands off to `resolveEdgeQuery` — same path user-written queries use

One resolver, two entry points. Labels are sugar.

### MCP tools

Three new read tools:

```typescript
list_edges(args: { featureId?: string; query?: EdgeQuery }): {
  edges: EdgeSegment[];
}

list_faces(args: { featureId?: string; query?: FaceQuery }): {
  faces: Array<{
    id: string;
    centroid: [number, number, number];
    normal: [number, number, number];
    surfaceType: string;
    area: number;
    label: string | null;
  }>;
}

list_face_labels(args: { featureId?: string }): {
  labels: Array<{ name: string; sketchId: string; centroid; area; normal }>;
}
```

`featureId` defaults to "the script's last returned shape" when omitted (matches existing `getShapeInfo` pattern). Total MCP surface goes from 9 to 12 tools.

## Diagnostic codes

| Code | When | Hint |
|---|---|---|
| `feature.edge-feature.no-edges-match` | Query/label/canonical resolves to zero edges | "The selection matched no edges. Use `list_edges` to see what's available on this shape." |
| `feature.edge-feature.ambiguous-selection` | `selectEdge` (singular) matches >1 edge | "Multiple edges match this query. Use `selectEdges` (plural) for all, or tighten with smaller `tolerance` / `near:`." |
| `feature.edge-feature.invalid-query` | Query has contradictory keys (e.g. both `convex: true` and `concave: true`) | "Query contains contradictory or unknown keys. Check the EdgeQuery type." |
| `feature.path.label-without-segment` | `.label()` called as first command or after `moveTo` / `close` | "label() must follow a lineTo or arc segment." |
| `feature.path.duplicate-label` | Same label name used twice in one sketch | "Each sketch label must be unique. Pick a different name." |
| `feature.face-feature.label-not-resolvable` | Shell/face-feature references a label that exists but can't resolve (e.g. shape was transformed after extrude) | "Apply shell before transforms, or use a query against the current geometry." |

All six get entries in `whyDidThisFail`.
