# v0.4-rc.13 — `mirror` + `reflect` + bundled rc.12 review fixes — Design Spec

**Goal:** Add symmetric-part construction primitives (`Shape.mirror`, `Shape.reflect`, `Sketch.reflect`) to the agent-facing API, and close the rc.12 review punch list (6 Important + 1 Nit).

**Architecture:** A bundled feature + quality milestone matching the rc.10/rc.11 cadence. The feature is a small DSL addition with three new methods, four new diagnostic codes, and one new feature kind in the lowerer; the review-fix block is structurally similar to rc.7's pattern of "close all findings from the prior review in one milestone."

**Tech Stack:** TypeScript 5.9, Replicad 0.20.5 (provides the underlying mirror operation via `shape.mirror(plane)` and 2D path reflection), vitest 4. No new dependencies.

---

## Why this milestone

**The feature side.** Symmetric parts are ubiquitous in mechanical CAD — brackets, mounting plates, housings — and an agent that can express "build the right half, mirror it to make the symmetric whole" in a single method call writes shorter, more readable scripts. Today, the agent has to write `s.union(s.translate(-x).rotateZ(180).translate(x))` or build the symmetric profile by hand in a path. Both are error-prone DSL workarounds. `Shape.mirror({ plane: 'yz' })` resolves the ergonomic gap in one verb.

The split into two methods (`mirror` for the joined symmetric-part shortcut, `reflect` for the pure-reflection primitive) is agent-first: it tells agents through the API surface that "these are two different operations" rather than baking a hidden `union` into a `mirror()` call (which is what some CAD systems do). Agents reading `list_api` see both verbs and can pick deterministically.

**The quality side.** The rc.12 review surfaced 6 Important findings and 6 Nits. Five of the Important findings are bounded mechanical fixes (synth-record discriminated union, runtime-import reachability sentinel, CHANGELOG accuracy + sweep completion, spawn.test.ts comment refresh, banner self-decoupling). One (banner self-decoupling) was deferred from rc.12 explicitly. Bundling them in rc.13 matches the rc.10/rc.11 cadence and prevents the punch list from accumulating.

## Architecture decisions made during brainstorming

These were resolved before spec write-up. They lock the spec; the plan should not re-litigate them.

### A1 — Two methods on `Shape` (`mirror` + `reflect`); one on `Sketch` (`reflect` only)

**Decision.** `Shape.mirror(plane)` returns the boolean union of the source and its reflection (the "symmetric part" shortcut). `Shape.reflect(plane)` returns the pure reflection (transform). `Sketch.reflect(axis)` returns the reflected sketch as a new sketch; there is no `Sketch.mirror` because sketches have no boolean union operation.

**Why.** Agents need both behaviors; bundling them under one name forces an awkward workaround for the less-common case. The split makes the API honest: each name describes what happens. Sketch-side asymmetry is justified by sketch semantics — a `Sketch.mirror` that quietly aliases `reflect` would lie about behavior. Agents reading `list_api` see the asymmetry and can infer "sketches are simpler than shapes; no boolean ops yet."

### A2 — Plane spec is cardinal-string OR `{ plane, offset }`

**Decision.** `Shape.mirror` and `Shape.reflect` accept either `'xy' | 'xz' | 'yz'` (cardinal plane through origin) or `{ plane: 'xy' | 'xz' | 'yz'; offset: number }` (plane parallel to a cardinal at the given offset). `Sketch.reflect` accepts `'x' | 'y'` or `{ axis: 'x' | 'y'; offset: number }`. The full point+normal arbitrary-plane form is deferred.

**Why.** Cardinal strings cover the 80% case (parts whose symmetry plane is axis-aligned). The offset form covers the 18% case (parts not centered at origin) without the agent-hostile `translate(-d).mirror('yz').translate(d)` workaround. The arbitrary-plane case is rare and can ship in a future rc once a real agent need surfaces.

### A3 — `reflect` is a transform; `mirror` is a feature

**Decision.** `Shape.reflect(plane)` appends a `{ kind: 'reflect', plane }` entry to the source shape's `transforms[]` array. The FeatureRecord id is unchanged. `Shape.mirror(plane)` produces a new FeatureRecord with `kind: 'mirror'`, `inputs.base = { kind: 'feature', id: source.id }`, and `metadata.plane`. The new feature lowers to a boolean union of the source and its reflection.

**Why.** `reflect` is a rigid-body transformation (same shape, different orientation) and belongs in the transforms array alongside `translate`/`rotate`. Treating it as a feature would create kernel inconsistency between rigid-body ops. `mirror` is a boolean union and belongs in the feature tree alongside `union`/`subtract` — both produce derived geometry from sources. The split also keeps diagnostic codes tight: only `mirror` can fail (booleans on degenerate inputs); `reflect` is matrix math and never fails at recompute.

### A4 — Canonical face refs become unresolvable after either operation

**Decision.** After `Shape.reflect(plane)`, canonical face refs (`{face: 'top'}`, etc.) on the result are unresolvable — same rule as `translate`/`rotate`. After `Shape.mirror(plane)`, canonical face refs are unresolvable because the result is a unioned non-primitive shape — same rule as `union`/`subtract`. Agents wanting to fillet/chamfer/shell a specific face on the result use queries (`{face: {atZ: 5}}`) or labels.

**Why.** Existing kernelCAD pattern. Reflections flip handedness (the `+x` face becomes `-x`), so even if canonical names were preserved, their semantics would shift in a way that's agent-confusing. Forcing queries on transformed/composite results is the established kernel rule and stays consistent.

### A5 — Diagnostic code reachability classification

**Decision.** All four new diagnostic codes (F4) are `reachable: 'engine-path'` per the rc.12 reachability classification — they fire during normal recompute and are agent-actionable through MCP.

**Why.** These codes describe failures the engine reaches: empty base shape, unsupported plane spec, OCCT boolean-union failure on degenerate inputs, sketch reflection on a degenerate path. None require direct lowerer invocation to surface; the recompute engine emits them naturally. Per the rc.12 error-attribution policy memo, only codes the engine short-circuits before reaching get `'direct-lowerer-only'`.

## Components

### Component 1 — `Shape.reflect(plane)` transform (closes F1)

**Where.**
- `src/capture/proxy.ts` — add `reflect(plane)` method on the Shape proxy, similar to existing `translate`/`rotate`. Method appends a transform entry; returns a new Shape with the same FeatureId.
- `src/capture/captureSession.ts` — add a transform-registration helper if `translate`/`rotate` don't already share one. Match the existing pattern.
- `src/intent/types.ts` — add `'reflect'` to the `TransformEntry` discriminated union: `{ kind: 'reflect'; plane: PlaneSpec }`.
- `src/backends/occt/occtBackend.ts` — add `reflect(plane: PlaneSpec)` instance method that calls Replicad's `shape.mirror(plane)` (Replicad's `mirror` IS a pure reflection per its docs — note the naming asymmetry between Replicad's primitive and our user-facing API; document this in the method's JSDoc).
- `src/backends/occt/transformPipeline.ts` (or wherever transforms are applied during lowering) — add a case for `'reflect'` that calls `occtBackend.reflect(plane)`.

**API shape.**

```typescript
type CardinalPlane = 'xy' | 'xz' | 'yz';
type PlaneSpec = CardinalPlane | { plane: CardinalPlane; offset: number };

class Shape {
  // existing methods...
  reflect(plane: PlaneSpec): Shape;
}
```

**Behavior.**
- `box(10,10,10).reflect('yz')` reflects across the yz-plane (x=0). The volume is unchanged.
- `box(10,10,10).reflect({ plane: 'yz', offset: 5 })` reflects across the plane x=5.
- Composes with other transforms: `box(10,10,10).translate(5,0,0).reflect('yz')` reflects after translation. Standard transform composition order.
- Canonical face refs after reflect: unresolvable, per A4.

**Diagnostic.** `feature.transform.invalid-plane` if the plane spec is malformed (this is a generic transform-level code; if the existing transform pipeline doesn't have a code for malformed transform args, we add one). Reflect itself never fails at recompute.

### Component 2 — `Shape.mirror(plane)` feature (closes F2)

**Where.**
- `src/capture/proxy.ts` — add `mirror(plane)` method on the Shape proxy. This creates a new FeatureRecord (not a transform), via `captureSession.feature(...)`.
- `src/capture/captureSession.ts` — register the mirror feature with `inputs.base`, `metadata.plane`.
- `src/intent/types.ts` — add `'mirror'` to `FeatureKind`.
- `src/backends/occt/occtLowerer.ts` — add `case 'mirror':` to the switch. Lowering: take base, compute its reflection, boolean-union the two.
- `src/backends/occt/occtBackend.ts` — uses existing `union(other)` + the new `reflect(plane)` from Component 1 to implement `mirror(plane)` as `this.union(this.reflect(plane))`. Or add a dedicated `mirror(plane)` method on the backend that does the same, for symmetry with the user-facing API. **Decision:** add the dedicated `mirror(plane)` instance method on OcctBackend so the lowerer code stays simple (`shape = base.mirror(plane)` rather than `shape = base.union(base.reflect(plane))`).

**API shape.**

```typescript
class Shape {
  // existing methods...
  mirror(plane: PlaneSpec): Shape;
}
```

**Behavior.**
- `box(10,5,5).translate(5,0,0).mirror('yz')` produces a 10×10×5 unioned shape (the original box on +x and its reflection on -x meeting at x=0).
- The result is a non-primitive composite shape; canonical face refs unresolvable per A4.
- `mirror` after other transforms composes naturally: the source's transforms are applied first, then the union of source + reflection is computed.

**Diagnostics.**
- `feature.mirror.no-base` — input base shape is missing (shouldn't happen via the script-runtime, but guards direct lowerer usage).
- `feature.mirror.invalid-plane` — the plane spec is malformed (rejected at capture if possible; emitted from lowerer if it slips through).
- `feature.mirror.failed` — Replicad/OCCT boolean union threw. The hint mentions degenerate-overlap (e.g. mirroring a shape exactly on the plane produces zero-thickness intersections).

### Component 3 — `Sketch.reflect(axis)` (closes F3)

**Where.**
- `src/capture/sketch.ts` — add `reflect(axis)` method to the Sketch class. Returns a new Sketch with reflected path commands.
- The implementation walks the sketch's command list and reflects each `(x, y)` coordinate per the axis spec. `'x'` reflects across the x-axis (negate y); `'y'` reflects across the y-axis (negate x); `{ axis: 'x', offset }` reflects across `y = offset` (`y' = 2*offset - y`); `{ axis: 'y', offset }` reflects across `x = offset` (`x' = 2*offset - x`). Arc commands need their `clockwise` flag flipped because reflection inverts winding direction.

**API shape.**

```typescript
type SketchAxis = 'x' | 'y';
type AxisSpec = SketchAxis | { axis: SketchAxis; offset: number };

class Sketch {
  // existing methods...
  reflect(axis: AxisSpec): Sketch;
}
```

**Behavior.**
- `path().moveTo(0,0).lineTo(10,0).lineTo(10,5).close().reflect('x')` produces the same profile reflected below the x-axis: `path().moveTo(0,0).lineTo(10,0).lineTo(10,-5).close()`.
- Arcs: `clockwise: true` becomes `clockwise: false` and vice versa (reflection inverts winding).
- Labels are preserved on their corresponding segments.

**Diagnostic.**
- `feature.sketch.reflect.invalid-axis` — axis spec is malformed.
- (No "failed" code — the operation is pure coordinate transformation; it cannot fail unless Replicad's path validation rejects the result, which is unlikely. If it does, the existing `feature.sketch.failed` code covers it.)

## Open questions for the spec reviewer

1. **Replicad's `shape.mirror(plane)` semantics — verify before plan-writing.** Replicad's API uses `mirror` as a transform (matches OpenSCAD's pattern). The user-facing kernelCAD API uses `mirror` for the union-based shortcut. The kernelCAD `Shape.reflect(plane)` calls Replicad's `shape.mirror(plane)`. **The plan should verify that Replicad's mirror is actually a pure reflection (not a union)**, document the naming asymmetry in the OcctBackend method's JSDoc, and add a unit test that exercises Replicad's mirror directly to prove the assumption.

2. **Plane offset's recompute behavior.** For `mirror({plane: 'yz', offset: 5})`, the implementation needs to translate the source by `-2*offset` along the plane normal, reflect, then... actually no. The cleaner formulation: reflect across the plane `x = offset` is equivalent to `x' = 2*offset - x`. Implement directly via Replicad's `mirror({ origin: [offset,0,0], normal: [1,0,0] })` (if Replicad accepts that form) or build the reflection matrix manually. Plan should pick one and verify correctness with a unit test.

3. **`Shape.mirror` on a shape that touches the plane.** A box at origin with `mirror('yz')` produces zero-thickness overlap on the yz plane. Replicad's boolean union may fail with a degenerate-geometry error, OR may succeed with the boundary identifying as the original face. The diagnostic `feature.mirror.failed` covers the failure case; the hint guides agents to translate or offset. **Plan should add an integration test that exercises this exact case** to confirm the failure mode and verify the hint helps.

These are flagged for the reviewer. None block plan-writing — they're testable assumptions that the plan's tasks verify in their TDD setup steps.
