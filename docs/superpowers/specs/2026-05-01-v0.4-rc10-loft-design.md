# v0.4-rc10 Sketch Loft + Bundled Quality Fixes — Design

**Date:** 2026-05-01
**Milestone:** v0.13.0-rc.10 (NORTHSTAR roadmap step in v0.4-rc trajectory: sketch loft + close 5 rc.9 review findings)

## Why

Sketch loft unlocks an entire geometry class agents currently can't reach: nozzles with varying cross-section, wings/airfoils interpolated between ribs, fairings, organic shells, gear teeth varying along thickness, transition pieces between mismatched flanges. The kernel (Replicad) exposes `Sketch.loftWith(otherSketches, loftConfig?)` and the top-level `loft(wires, ...)` already; rc.10 surfaces it through a stable agent-friendly TypeScript API.

Bundled with loft: the rc.9 review found 1 Critical bug and 5 Important findings that are cheap to ship now and prevent compounding drift.

- **C1 (Critical):** `Shape.lower()` cache returns stale geometry after `translate`/`rotate`/`scale`. Cache invalidates on `records.length` but `appendTransform` mutates `record.transforms` in place — length unchanged, cache returns un-transformed backend. Silent incorrect results — agents have no signal. Must fix first.
- **I1:** `keyof EdgeQuery` typing only catches "key in array but not in type", not vice versa. Magic number `14` in test is the only guard. Replace with true compile-time exhaustiveness check.
- **I2:** No drift sentinel between `server.ts:TOOLS` and the call-handler switch — analog of the gap that just bit `list_api`.
- **I5:** L-bend sweep bbox assertion is too loose (`max[0] > 28` allows wrong-axis sweeps to pass). Tighten to match the pipe test rigor.

(Other rc.9 review findings — I3, I4, I6, nits — deferred to rc.11.)

## Scope

### `Sketch.loft(other, opts?)` signature

```typescript
type PlaneSpec = {
  plane: 'XY' | 'YZ' | 'XZ';
  origin: [number, number, number];   // world position of the plane's origin
};

interface LoftOptions {
  /**
   * Z-stack the input sketches with this axial spacing (mm). The first sketch
   * stays at z=0; the second at z=spacing; the third at 2*spacing; etc.
   * Used when `planes` is not provided. Default: 10.
   */
  spacing?: number;

  /**
   * Explicit per-sketch plane specifications. If provided, takes precedence
   * over `spacing`. Length must equal total section count (1 + others.length).
   * The first entry positions the THIS sketch; remaining entries position
   * `others` in order.
   */
  planes?: PlaneSpec[];

  /**
   * If true, transitions between sections are STRAIGHT (ruled surface) rather
   * than smoothly interpolated. Use for polyhedral / faceted lofts.
   */
  ruled?: boolean;

  /** Optional explicit start point before the first sketch. */
  startPoint?: [number, number, number];

  /** Optional explicit end point after the last sketch. */
  endPoint?: [number, number, number];
}

class Sketch {
  loft(other: Sketch | Sketch[], opts?: LoftOptions): Shape;
}
```

### Validation

- `other` is `Sketch` or `Sketch[]`. After flattening, total section count = `1 + (Array.isArray(other) ? other.length : 1)`. Must be ≥ 2 (otherwise → `feature.loft.empty-sections`).
- If `opts.planes` provided, `planes.length` must equal section count (otherwise → `feature.loft.invalid-planes`).
- If `opts.planes` AND `opts.spacing` both provided, `planes` wins (documented; not an error).
- Replicad-thrown errors during loft → caught and re-emitted as `feature.loft.failed`.

### Diagnostic codes (3 new)

| Code | When | Hint |
|---|---|---|
| `feature.loft.empty-sections` | Total section count < 2 | "Loft needs at least 2 sketches. Pass another `path().close()` sketch (or array of them) as the first argument." |
| `feature.loft.invalid-planes` | `planes.length` doesn't match section count | "If you pass `opts.planes`, its length must equal the total number of sections (1 + others.length). Or omit planes and use `opts.spacing` for axial z-stacking." |
| `feature.loft.failed` | Replicad rejects the loft (e.g. self-intersecting interpolation) | "OCCT could not loft these sections. Common causes: profiles with very different vertex counts (loft fails to match edges), tightly-spaced sections with mismatched orientation, or non-planar input. Try `ruled: true` for sharp transitions, or pre-rotate sections to align orientations." |

## Architecture

### Capture layer (`src/capture/sketch.ts`)

`Sketch.loft(other, opts?)` registers a `'loft'` FeatureRecord (`'loft'` already exists in `FeatureKind` per `src/intent/types.ts:54`):

```typescript
loft(other: Sketch | Sketch[], opts: LoftOptions = {}): Shape {
  const others = Array.isArray(other) ? other : [other];
  const allSketches = [this, ...others];
  const inputs: Record<string, FeatureRef> = {};
  // sketch_0 = this, sketch_1 = others[0], etc.
  for (let i = 0; i < allSketches.length; i++) {
    inputs[`sketch_${i}`] = { kind: 'feature', id: allSketches[i].id };
  }
  return this.session.createShape({
    kind: 'loft',
    inputs,
    params: {
      profileKind: { expression: "'sketch'", unit: 'unitless', evaluated: 0 },
      spacing: { expression: String(opts.spacing ?? 10), unit: 'mm', evaluated: opts.spacing ?? 10 },
      ruled: { expression: String(opts.ruled ?? false), unit: 'unitless', evaluated: opts.ruled ? 1 : 0 },
      sectionCount: { expression: String(allSketches.length), unit: 'unitless', evaluated: allSketches.length },
    },
    metadata: {
      planes: opts.planes,
      startPoint: opts.startPoint,
      endPoint: opts.endPoint,
    },
  });
}
```

The `sketch_N` input naming (vs a single-key array) keeps the inputs map flat — matches existing extrude/sweep `inputs.sketch` convention with index suffix for multi-input.

### Backend (`src/backends/occt/occtBackend.ts`)

New static factory:

```typescript
static loftFromSketches(
  sketches: OcctBackend[],         // sketch-tagged backends, in order
  planes: PlaneSpec[],             // resolved planes (lowerer fills these from spacing if needed)
  opts: { ruled?: boolean; startPoint?: Vec3; endPoint?: Vec3 } = {},
): OcctBackend {
  if (sketches.length < 2) {
    throw new Error('OcctBackend.loftFromSketches: need at least 2 sketches');
  }
  if (planes.length !== sketches.length) {
    throw new Error(`OcctBackend.loftFromSketches: planes count ${planes.length} must equal sketches count ${sketches.length}`);
  }
  // Lift each sketch onto its target plane, then loft via Replicad.
  const lifted = sketches.map((s, i) => {
    if (s.kind !== 'sketch' || !s._drawing) {
      throw new Error(`OcctBackend.loftFromSketches: input ${i} is not a sketch.`);
    }
    return s._drawing.sketchOnPlane(planes[i].plane, planes[i].origin);
  });
  // Replicad's loftWith expects a single Sketch and an array (or one) of others.
  const [first, ...rest] = lifted;
  const loftConfig: { ruled?: boolean; startPoint?: import('replicad').Point; endPoint?: import('replicad').Point } = {};
  if (opts.ruled !== undefined) loftConfig.ruled = opts.ruled;
  if (opts.startPoint) loftConfig.startPoint = opts.startPoint as unknown as import('replicad').Point;
  if (opts.endPoint) loftConfig.endPoint = opts.endPoint as unknown as import('replicad').Point;
  const lofted = (first as unknown as { loftWith: (others: unknown[], cfg: typeof loftConfig) => import('replicad').Shape3D })
    .loftWith(rest, loftConfig);
  return new OcctBackend(lofted);
}
```

### Lowerer (`src/backends/occt/occtLowerer.ts`)

New `'loft'` arm parallel to `'extrude'`/`'revolve'`/`'sweep'`. Validates section count, derives planes from `spacing` if `metadata.planes` not provided, dispatches to the backend factory:

```typescript
case 'loft': {
  const profileKind = String(r.params.profileKind.expression).replace(/'/g, '');
  if (profileKind === 'sketch') {
    const sectionCount = r.params.sectionCount.evaluated;
    if (sectionCount < 2) {
      diagnostics.push({ ..., code: 'feature.loft.empty-sections', ... });
      return ...;
    }
    // Collect sketch_0 through sketch_{N-1} from inputs.byKey
    const sketches: OcctBackend[] = [];
    for (let i = 0; i < sectionCount; i++) {
      const s = inputs.byKey[`sketch_${i}`] as OcctBackend | undefined;
      if (!s) {
        diagnostics.push({ ..., code: 'feature.loft.bad-sketches', message: `loft missing input sketch_${i}` });
        return ...;
      }
      sketches.push(s);
    }
    // Resolve planes
    const explicitPlanes = (r.metadata as { planes?: unknown })?.planes;
    let planes: PlaneSpec[];
    if (Array.isArray(explicitPlanes)) {
      if (explicitPlanes.length !== sectionCount) {
        diagnostics.push({ ..., code: 'feature.loft.invalid-planes', ... });
        return ...;
      }
      planes = explicitPlanes as PlaneSpec[];
    } else {
      // Z-stack with spacing
      const spacing = r.params.spacing.evaluated;
      planes = sketches.map((_, i) => ({
        plane: 'XY' as const,
        origin: [0, 0, i * spacing] as [number, number, number],
      }));
    }
    const ruled = (r.params.ruled?.evaluated ?? 0) > 0.5;
    const startPoint = (r.metadata as { startPoint?: Vec3 })?.startPoint;
    const endPoint = (r.metadata as { endPoint?: Vec3 })?.endPoint;
    try {
      shape = OcctBackend.loftFromSketches(sketches, planes, { ruled, startPoint, endPoint });
    } catch (e) {
      const msg = e instanceof Error ? e.message : String(e);
      diagnostics.push({ ..., code: 'feature.loft.failed', message: `OCCT loft failed: ${msg}` });
      return ...;
    }
  } else {
    // unsupported-profile
  }
  break;
}
```

### Bundled — C1 fix

In `src/capture/proxy.ts`, `Shape.lower()`'s cache:

```typescript
private _loweredBackend?: OcctBackend;
private _loweredAtRecordCount?: number;
private _loweredAtTransformCount?: number;   // NEW

async lower(): Promise<OcctBackend> {
  const records = this.session.getRecords();
  const ownRecord = records.find(r => r.id === this.id);
  const transformCount = ownRecord?.transforms.length ?? 0;
  if (
    this._loweredBackend &&
    this._loweredAtRecordCount === records.length &&
    this._loweredAtTransformCount === transformCount
  ) {
    return this._loweredBackend;
  }
  // ... existing lowering ...
  this._loweredBackend = shape;
  this._loweredAtRecordCount = records.length;
  this._loweredAtTransformCount = transformCount;
  return shape;
}
```

The cache key now includes the THIS shape's transform count. After `Shape.translate(...)` (which appends to `transforms`), the next `Shape.lower()` re-runs recompute. Note: this only fixes invalidation for transforms applied to THIS shape; transforms on upstream shapes are already covered by `records.length` (each transform-bearing shape owns its own record).

### Bundled — I1 fix (compile-time exhaustiveness)

In `src/backends/occt/queryKeys.ts`, add an exhaustiveness check that fails compilation if a key is in the type but missing from the array:

```typescript
import type { EdgeQuery, FaceQuery } from './edgeQueries';

export const EDGE_QUERY_KEYS: ReadonlyArray<keyof EdgeQuery> = [
  'atZ', 'atX', 'atY', 'near', 'within', 'parallel', 'perpendicular',
  'convex', 'concave', 'minAngle', 'maxAngle', 'ofCurveType',
  'tolerance', 'angleTolerance',
];

// Compile-time exhaustiveness check: `Exclude<all keys, listed keys>` must
// be `never`. If a future rc adds `EdgeQuery.foo` and forgets the array,
// `Exclude<keyof EdgeQuery, 'atZ' | ... | 'angleTolerance'>` becomes `'foo'`,
// and the assignment below fails compilation.
type _EdgeQueryKeysExhaustive = Exclude<keyof EdgeQuery, typeof EDGE_QUERY_KEYS[number]>;
const _edgeKeysExhaustive: [_EdgeQueryKeysExhaustive] extends [never] ? true : false = true;
void _edgeKeysExhaustive;

export const FACE_QUERY_KEYS: ReadonlyArray<keyof FaceQuery> = [
  'atZ', 'atX', 'atY', 'parallelTo', 'inPlane', 'ofSurfaceType',
  'containsPoint', 'near', 'tolerance',
];

type _FaceQueryKeysExhaustive = Exclude<keyof FaceQuery, typeof FACE_QUERY_KEYS[number]>;
const _faceKeysExhaustive: [_FaceQueryKeysExhaustive] extends [never] ? true : false = true;
void _faceKeysExhaustive;
```

The `[X] extends [never] ? true : false` distributing trick yields `true` only when `X` is `never` (no missing keys). Removes the magic-number `14` / `9` test fragility from rc.9.

```typescript
import { describe, it, expect } from 'vitest';

describe('MCP server: TOOLS array ↔ call-handler switch parity', () => {
  it('every tool in TOOLS has a matching case in the switch (and vice versa)', () => {
    // Read server.ts source as text and verify both surfaces match.
    const fs = require('node:fs');
    const path = require('node:path');
    const src = fs.readFileSync(
      path.join(__dirname, '../../../src/mcp/server.ts'),
      'utf8',
    );
    // Extract names from TOOLS array (lines like `    name: 'evaluate_script',`)
    const toolNameRe = /name:\s*'([a-z_]+)'/g;
    const toolsBlock = src.slice(src.indexOf('const TOOLS'), src.indexOf('];', src.indexOf('const TOOLS')));
    const toolNames = new Set<string>();
    let m: RegExpExecArray | null;
    while ((m = toolNameRe.exec(toolsBlock)) !== null) toolNames.add(m[1]);
    // Extract names from switch (lines like `      case 'evaluate_script':`)
    const caseRe = /case\s+'([a-z_]+)':/g;
    const caseNames = new Set<string>();
    while ((m = caseRe.exec(src)) !== null) caseNames.add(m[1]);
    // Symmetric difference must be empty.
    const inToolsNotSwitch = [...toolNames].filter(n => !caseNames.has(n));
    const inSwitchNotTools = [...caseNames].filter(n => !toolNames.has(n));
    expect(inToolsNotSwitch).toEqual([]);
    expect(inSwitchNotTools).toEqual([]);
  });
});
```

(Source-text parsing is acceptable here — the alternative is exposing internal arrays from `server.ts`, which is a wider surface change. The regex approach is robust enough for the documented `name: '...'` and `case '...':` patterns the codebase already uses uniformly.)

## Risks

- **`loftWith` with multi-face profiles** — same multi-face concern as sweep. The Replicad `Sketch.loftWith` API accepts a single Sketch (or array of single Sketches). If a future API allows `path()` to produce `Sketches` (plural), loft hits the same `face is not a function` issue. Mitigation: same `liftSketchToFace` helper pattern is reusable; defer until needed.
- **Profile edge-count mismatch** — Replicad's loft fails when input profiles have very different vertex counts (e.g. circle approximated with 32 segments vs square with 4 segments). Surfaces as `feature.loft.failed`; hint guides agent to use comparable section detail.
- **Plane orientation mismatch** — if input sketches sit on perpendicular planes (XY vs YZ), Replicad may produce a self-intersecting loft. Documented in the explicit-planes API; agents control orientation via `planes:`.
