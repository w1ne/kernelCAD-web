# v0.4-rc4 Sketch Revolve — Design

**Date:** 2026-04-30
**Milestone:** v0.13.0-rc.4 (NORTHSTAR roadmap step in v0.4-rc trajectory: sketch revolve)
**Status:** approved, ready for implementation plan

## Context

Following the v0.4-rc trajectory:
- **rc.1** — `remove_feature` MCP write tool
- **rc.2** — sketch builder (line-only `path()`)
- **rc.3** — `tangentArc` (first curved 2D segment)
- **rc.4 (this spec)** — sketch revolve (terminal `.revolve()` on path)

The `path()` builder currently terminates only with `.extrude(d)`, producing prismatic solids. Adding `.revolve()` unlocks an entire new geometry class: solids of revolution (washers, mugs, screws, knobs, axles, vases, gear teeth profiles, ergonomic handles). This is the largest geometric unlock per single feature in the trajectory so far — agents compose dozens of new part types from one new method.

## Goals

1. Agents can build any solid of revolution by drawing a 2D profile in the XZ plane and revolving 360° around the Z axis.
2. API is parallel to `.extrude(d)` — terminal call on `path()`, no separate builder type.
3. Reuse existing path vocabulary (`moveTo`, `lineTo`, `tangentArc`, `close`) without modification.
4. Validation surfaces clear diagnostics when the profile is malformed (crosses axis, empty).

## Non-goals

- Partial angles (`{ angleDeg }`) — deferred; needs wedge-boolean implementation.
- Non-Z axes (`{ axis }`) — deferred; needs plane derivation.
- Sweep along path (different feature kind, much larger scope).
- Sketch labels for face references — separate milestone.

## API

```typescript
// Washer: rect profile rotated around Z
return path()
  .moveTo(innerRadius, 0)
  .lineTo(outerRadius, 0)
  .lineTo(outerRadius, height)
  .lineTo(innerRadius, height)
  .close()
  .revolve();   // full 360° around Z axis; profile interpreted as XZ-plane

// Mug body: tangentArc curves into a flared profile
return path()
  .moveTo(20, 0)
  .lineTo(20, 60)
  .tangentArc(25, 80)
  .lineTo(25, 90)
  .lineTo(0, 90)   // top edge meets axis
  .lineTo(0, 0)
  .close()
  .revolve();
```

**Convention:** the path coordinates `(x, y)` are interpreted as `(radial-X, axial-Z)`. The first coordinate is distance from the rotation axis; the second is height along the axis.

`.revolve()` takes no parameters. Returns a `Shape` (same return type as `.extrude(d)`).

## Architecture

### Capture layer (`src/capture/sketch.ts`)

The `Sketch` class already has `.extrude(d)`. Add a parallel `.revolve()` method:

```typescript
revolve(): Shape {
  const featureId = session.register({
    kind: 'revolve',
    metadata: {
      profileKind: 'sketch',
      commands: this.commands,
    },
  });
  return session.createShape(featureId);
}
```

The metadata structure mirrors `extrude` with `profileKind: 'sketch'` (see rc.2). The `commands` array carries the same `SketchCommand[]` shape so the lowerer can replay verbatim.

### FeatureKind / metadata

`'revolve'` already exists in `FeatureKind` (used by `revolveRect`). The metadata gains a new `profileKind: 'sketch'` discriminant. Existing rect-profile revolve continues to work unchanged.

### Backend (`src/backends/occt/occtBackend.ts`)

New static factory:

```typescript
static revolveFromSketch(commands: SketchCommand[]): OcctBackend {
  if (!initialized) throw new Error('OCCT not initialized — call initOcct() first');
  // First command must be moveTo. Each subsequent lineTo/tangentArc replays
  // verbatim on the replicad pen. Final command must be close.
  const first = commands[0];
  if (first?.kind !== 'moveTo') throw new Error('sketch must begin with moveTo');
  let pen = replicad.draw([first.x, first.y]);
  // ... iterate up to close (mirroring fromSketchCommands but ending in .sketchOnPlane('XZ').revolve)
  const sketch = pen.close().sketchOnPlane('XZ');
  const single = sketch as unknown as {
    revolve: (axis?: [number, number, number]) => ReplicadShape3D;
  };
  return new OcctBackend(single.revolve([0, 0, 1]));
}
```

### Lowerer (`src/backends/occt/occtLowerer.ts`)

The existing `'revolve'` case lowers `revolveRect`. Extend it with a `profileKind` discriminant analogous to the `extrude` arm:

```typescript
case 'revolve': {
  const meta = record.metadata;
  if (meta.profileKind === 'sketch') {
    shape = OcctBackend.revolveFromSketch(meta.commands);
  } else {
    // existing rect path (unchanged)
    shape = OcctBackend.revolveRect(meta.w, meta.h, meta.offsetX, meta.angleDeg);
  }
  break;
}
```

If `profileKind` is missing on existing records, default to the rect branch (back-compat).

### Validation / diagnostics

Two new diagnostic codes, registered in `whyDidThisFail.ts` hint table:

- `feature.revolve.crosses-axis` — any sketch point has `x < 0`. Hint: "A revolve profile must stay on one side of the rotation axis. Ensure all path coordinates have x ≥ 0 (the first coordinate is the radial distance)."
- `feature.revolve.empty-profile` — profile contains no segments (only `moveTo` + `close`). Hint: "A revolve profile needs at least one lineTo or tangentArc segment to define a closed area."

Both are surfaced from `revolveFromSketch` before calling Replicad. Replicad-thrown errors are caught and re-emitted as `feature.revolve.failed` (existing pattern from rc.3 sketch failures).

## Test plan

1. `.revolve()` returns a `Shape` and registers a feature with `kind: 'revolve'`, `metadata.profileKind: 'sketch'`.
2. The registered feature's `metadata.commands` exactly matches the input path commands array.

### Unit — backend (`tests/unit/backends/occt/occtBackend.revolveSketch.test.ts`)

3. **Washer volume:** rect profile (innerR=10, outerR=20, height=5) → volume ≈ `π × (20² − 10²) × 5 = 1500π ≈ 4712.4`. Bound: `> 4500 && < 4900`.
4. **Solid cylinder via revolve:** rect from x=0 to x=10, height 20 → volume ≈ `π × 10² × 20 = 6283.2`. Bound: `> 6200 && < 6400`.

6. **Axis-cross diagnostic:** profile with a point at `x = -1` produces `feature.revolve.crosses-axis` and no shape.
7. **Empty profile diagnostic:** path with only `moveTo(0,0).close()` produces `feature.revolve.empty-profile`.

## Risks & mitigations

- **Replicad's `Sketch.revolve` quirks** (full-turn only confirmed in rc.0 work). The `revolveFromSketch` factory uses the same call shape as the proven `revolveRect`, so this is low risk.
- **Axis-touching profiles** (point at `x=0`) are valid (e.g., a sphere from a half-disc). Test 5 (mug body has `(0, 90)` and `(0, 0)`) explicitly covers this — diagnostic is `x < 0`, not `x ≤ 0`.
- **TangentArc across the axis** (e.g., tangentArc terminating at `x=0`) — covered by test 5 if the profile transitions from positive-x to axis cleanly. Replicad handles this; if it throws, surfaces as `feature.revolve.failed`.
