- [ ] **Task 2 — `export_stl` validation + error paths.** Implements spec Component 1 / F2.
  - Within the new `src/mcp/tools/exportStl.ts`, ensure all the spec's error paths are handled:
    - Missing both `file` and `code` → `{ ok: false, error: "Must provide either { file } or { code }." }`
    - Missing `output_path` → `{ ok: false, error: "Required: output_path" }`
    - Script lowering fails → `{ ok: false, diagnostics: [...] }` (no STL written)
    - File write fails (perms, missing dir, etc) → `{ ok: false, error: "Cannot write to <path>: <reason>" }`
    - Optional `feature_id` not found in records → `{ ok: false, error: "feature_id '<id>' not found." }`
  - May be implemented inline with Task 1 if cleaner. Plan-time judgment: if Task 1's tool implementation is short (~80 lines including all paths), make this one combined task.
  - Tests: covered by Task 3.

- [ ] **Task 3 — `export_stl` integration test.** Implements spec Component 1 / F3.
  - Create: `tests/integration/mcp/exportStl.test.ts`. Tests:
    1. Round-trip: build a 10x10x10 box, export to a temp file, assert file exists, byte_count > 0, valid binary STL header (first 80 bytes are header text or zeros, then 4-byte little-endian triangle count).
    2. Error path: malformed code (e.g. `return undefined`) → no file written; diagnostics returned.
    3. Feature-specific: multi-feature script + `feature_id` → exports the named feature, not the last.
    4. Output path validation: missing directory → returns ok:false with descriptive error.
  - Use `os.tmpdir()` + a uuid suffix for the temp file to avoid test interference. Clean up in afterEach.
  - Commit: `test(integration): cover export_stl round-trip + error paths`.
